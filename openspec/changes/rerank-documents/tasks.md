- [ ] 1.2 `allocate_documents(candidates, limit) -> list[list[Doc]]`: pure and deterministic, exactly the D2 three passes (page primaries; remaining fetched chunks in `(distance, file_path, chunk_index)` order under the cap of 3; then title or excerpt primaries in unreranked order). `Doc` carries the text plus an opaque back-reference to its chunk row (or `None` for a title or excerpt document) for D4.
- [ ] 1.3 `rerank_candidates(query, groups)`: the flattened list in one `score` call; validation unchanged, judged over the document count; per-note `max`, `best` = first maximal document in allocation order; order `(−max, position)`. `RerankOutcome` gains `best` and `documents`. `candidates` = groups. The state precedence and `no_candidates` are unchanged (zero groups means no request).
- [ ] 1.4 Unit tests: the **≤ 50 proof test**, a property/table test over `limit ∈ {1, 10, 11, 15, 30, 50}` × chunk distributions (one note with 60 rows, 50 single-row notes, 250 rows over 50 notes, stale and keyword-only mixes). It asserts `documents ≤ 50`, `≤ 3` per note, a note's first document is its primary, each of the first `min(limit, m)` notes holds ≥ 1, no document is a row outside the fetched list, pass 2 is in distance order (the spec's A/B scenario), equidistant ties fall to `(file_path, chunk_index)`, the same input twice gives the same allocation, and with `limit ≤ 10` over ≤ 50 rows every fresh row is a document except a note's rows past its third. The builder: the prefix is always whole at 300 + 2,000; a stamp-1 vs stamp-2 chunk with a 9-space run; a NULL prefix gives the legacy document; the code-point cut on an astral character at the boundary.
