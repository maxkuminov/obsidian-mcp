Refs #367 (the reranker half). The embedding-model / query-instruction half of #367 is a separate change, `heading-chunks`, and nothing here depends on it.

## Why

`semantic_search` orders notes by the cosine distance of one query vector to one chunk vector. A bi-encoder ranks recall well and fine order poorly: the right note is usually in the 50-chunk overfetch, often not at rank 1. A cross-encoder reranker reads the query and each candidate together and fixes exactly that. Anthropic measured top-20 retrieval failure 2.9% → 1.9% from reranking on top of hybrid retrieval. Ollama has no rerank endpoint (ollama#3368, open since 2024-03), but llama.cpp's `llama-server` serves `/v1/rerank` for `bge-reranker-v2-m3` and `Qwen3-Reranker-0.6B` GGUFs. The cost is the problem. On a laptop CPU, scoring 10 documents takes about 6 s, which rules it out as a default path. On a small shared GPU, 50 candidates are plausibly sub-second, but nobody has measured it. So the reranker ships **opt-in, per call, behind an operator-configured endpoint**, with hard failure semantics: it either reorders the page visibly or leaves it exactly as it was, visibly. The search evaluation harness (#356) exists now, so the gain can be measured on the operator's own judgments before anyone recommends turning it on.

**Sequencing.** This change is sequenced **after `hybrid-search`** (#354), which merged on 2026-10-30 before implementation began. The `rerank` argument therefore lands on both `semantic_search` and `hybrid_search` (task 0.1 rebased the deltas onto the merged 28-tool text).

## What Changes

- **Four settings, all optional:** `RERANK_URL` (default empty, meaning the feature is absent), `RERANK_MODEL` (sent as `model` in the request body), `RERANK_TIMEOUT_MS` (default 1500, range 100–10000) and `RERANK_ALLOW_PLAINTEXT` (default false). `RERANK_URL` is the **full endpoint URL**. It must be `https`, or `http` to a literal loopback host, unless `RERANK_ALLOW_PLAINTEXT=true`. The same parser and rules as the embedding hop (#185) apply. A URL that breaks the policy refuses boot, like `OLLAMA_URL`. A reranker that is merely *down* never does.
- **One wire format in v1: the Jina-compatible `/v1/rerank`** served by `llama-server` (and by vLLM and Infinity). The request is `{"model", "query", "documents", "top_n"}` and the response is `{"results": [{"index", "relevance_score"}]}`. TEI's native `/rerank` (`texts` → `[{index, score}]`) and Cohere's v2 are documented limitations, not supported.
- **`rerank_http_client`**, a sibling of `embedding_http_client` in `src/services/transport_security.py`, with the same transport policy: `trust_env=False`, `follow_redirects=False`, and the `EMBEDDING_CA_FILE` context (else certifi). It is one pooled client per process with at most 2 connections, closed at shutdown. Every call has one wall-clock deadline (`RERANK_TIMEOUT_MS`), and the response body is read under a 1 MiB cap.
- **A `rerank: bool = false` argument on `semantic_search` and `hybrid_search`**, always in the schema, so the tool contract is the same on every deployment (1.0 tool-contract promise). With `rerank=false` the output is byte-identical to today. With `rerank=true` the server scores **only the candidates already fetched**, never running a second retrieval: the deduped notes of the existing overfetch, before truncation to `limit`, capped at **50 notes**. The unit scored is the **note**, represented by its title and its best-matching stored chunk (design D4). Candidates come from one shared service (`semantic_candidates`) that the harness arm also uses, and their text is an internal field taken before the 500-character result cut. The page is then the first `limit` candidates by `rerank_score`. `rerank=true` responses always use hybrid-search's quoted-object row encoding, with a server-formatted `rerank_score` after the separator, and the header carries `reranked: true`.
- **Never a silent partial, never a failed search.** On timeout, transport error, HTTP error, oversize or malformed body, a result count that differs from the candidate count, a duplicate or out-of-range index, or a non-finite score, the tool returns the **unreranked** page (vector order for `semantic_search`, fused order for `hybrid_search`; the same rows, fields and previews in the `rerank=true` encoding) with `reranked: false (<reason>)`, where the reason comes from a closed code set. The same marker carries `not_configured` (no `RERANK_URL`), `probe_failed`, `probe_skipped` (sandbox) and `no_candidates`. Endpoint text is never rendered.
- **A startup probe.** When `RERANK_URL` is set, the lifespan scores one known-relevant and one known-irrelevant document for a fixed query, **in both document orders**, under a 10 s deadline. Wrong order, a tie, an invalid response or an unreachable endpoint **disables the feature** and logs one CRITICAL. The lifespan does **not** refuse to start. A background re-probe (60 s, doubling to 10 min) re-enables the feature when the reranker comes up. `/health` gains `rerank: "enabled" | "disabled" | "absent"`, with no URL, host or error text, and it stays HTTP 200 with the top-level `status` unaffected. `MCP_SANDBOX_MODE` skips the probe and the URL policy.
- **Concurrency**: a `rerank=true` call stays in its tool's class (`embedding` for both tools). The class is per tool, not per argument, so `CLASS_MAPPING_VERSION` does not change. The slot is held through the rerank hop, which extends the hold by at most `RERANK_TIMEOUT_MS`. **No database connection is held during the reranker call.**
- **Telemetry and harness**: the usage row records `rerank` (the argument), `reranked`, `rerank_reason`, `rerank_ms` and `rerank_candidates`, and `result_paths` is re-recorded in the reranked order. A `reranked: false` row carries no `error` marker. The harness gains `scripts/search_eval_arms/rerank.py` with `make_semantic_arm` (membership `semantic`) and `make_hybrid_arm` (membership `keyword_or_semantic`), which call the same production rerank function. Each factory runs the probe and refuses to start if it fails, and each arm fails the run on any `reranked: false` answer. Separate factories are needed because `--arm-opt` is run-global, and the incumbent `semantic` arm has to stay unreranked in the same report. `hybrid_k` is read through the hybrid-search change's `ARM_OPTS` passthrough.
- **Docs in the same PR**: README (argument, settings table), `.env.example`, DEPLOYMENT.md (an example of running `llama-server --reranking` with a reranker GGUF, as an example only), `docs/architecture/search.md` (a new "Reranking (#367)" section), `docs/architecture/indexing-and-embeddings.md` (the third outbound hop, beside "Embedding providers"), `docs/architecture/rate-limits.md` (the slot-hold sentence), `docs/architecture/usage-attribution.md` (params keys), and CLAUDE.md (a key-decisions bullet; the `semantic_search` amendment in the MCP-tools section).

The README default is unchanged: no reranker is configured. No migration.

## Capabilities

### New Capabilities

- `reranker`: the `RERANK_*` settings and their validation; the rerank client and its transport policy; the wire format and response validation; the startup probe, the process state and `/health`; the `rerank` argument on `semantic_search` and (by name) on `hybrid_search` as `hybrid-search` defines it; candidate selection, the scored unit and the ordering; the closed reason-code set and fallback; rendering; telemetry; concurrency and connection holding.

### Modified Capabilities

- `search-quality`: MODIFIED "Search calls record per-phase timing" (`rerank_ms` and the rerank keys on `semantic_search`, and `result_paths` recorded in the final order).
- `search-evaluation`: MODIFIED "Replay SHALL connect only to the named URL…" (a rerank arm's only non-database hop is `RERANK_URL` through the rerank client), and ADDED "The harness SHALL ship replayable rerank arms that fail the run rather than score an unreranked answer".
- `mcp-request-routing`: MODIFIED "Tool metadata SHALL leave the published tool surface otherwise unchanged" (an amendment entry for `semantic_search` differing only by the optional `rerank` property, and the `hybrid_search` additions entry carrying it too; rebased onto the merged 28-tool text by task 0.1).
- `internal-transport-security`: MODIFIED "The server SHALL report each outbound hop's transport once at startup" (a rerank line).
- `security-event-logging`: MODIFIED "A plaintext internal hop SHALL be recorded once per process start as a catalogued event" (`reason` gains `rerank`).

`hybrid_search`'s `rerank` behaviour is specified in the `reranker` capability and refers to the tool by name; the `hybrid-search` capability carries no delta from here.

## Impact

- **Code**: `src/config.py` (four settings, a policy validator); `src/services/transport_security.py` (`rerank_http_client`, the transport log line); `src/services/rerank.py` (new: client lifecycle, request, validation, the probe, process state); `src/main.py` (the probe in the lifespan, client close at shutdown, the `/health` field); `src/services/embeddings.py` (an untruncated candidate list for `semantic_search`, with the same statements); `src/mcp_server/tools.py` (`rerank` on `semantic_search_impl` and `hybrid_search_impl`, rendering); `src/mcp_server/server.py` (signatures and docstrings); `src/services/security_events.py` (the reason value); `scripts/search_eval_arms/rerank.py` (new).
- **Tests**: a fake reranker server fixture (an in-process ASGI app over a loopback port) that exercises a correct order, an inverted order, a timeout, HTTP 500, a redirect, a malformed body, an oversize body, a count mismatch, duplicate and out-of-range indices, NaN, ±Inf, and probe ordering; settings validation; the byte-identity of `rerank=false`; render forgery cases; telemetry; the no-connection-during-rerank checkout test; the harness arms; the tool-schema amendment.
- **Operations**: opt-in. Deployments without `RERANK_URL` see a new optional argument that always answers `reranked: false (not_configured)` and nothing else. With a reranker, `rerank=true` calls hold the `embedding` slot up to `RERANK_TIMEOUT_MS` longer, and queue-mode readiness evidence should be read with that in mind (design L7).
- **Gates**: a search-path change. The CLAUDE.md eval gate row applies (snapshot, then `make search-eval` with the rerank arm against `semantic` as `BASELINE`, attached only if attachable), and the adversarial Codex pass is mandatory.
