## Why

Three findings from the 2026-09-04 OWASP ASVS 5.0 assessment are still open at the **edge** of the deployment — the layer between a client and the first line of application code. Each is independently verified on the production host; each is a place where the server either accepts something it should refuse or cannot express what it trusts.

- **#196 (V4.1.2)** — Traefik's own `http-catchall` router (`HostRegexp(`.+`)` on the `http` entrypoint, middleware `redirect-to-https`) redirects every plaintext request to HTTPS, and the repo's `obsidian-mcp-api-rtr` binds only `https`, so **nothing in this tree refuses plaintext**. An agent misconfigured with `http://…/mcp` sends `Authorization: Bearer omcp_…` in cleartext, gets a **307** on POST, and — because the MCP Python SDK hard-codes `follow_redirects=True` and httpx deliberately *keeps* `Authorization` across a direct http→https redirect — replays successfully over TLS and never notices. The same holds for `POST /token`, which carries the authorization code, `code_verifier` and `client_secret` in the form body. The leak is silent by construction: every request succeeds.
- **#189 (V15.3.4)** — proxy trust is expressed **twice and inconsistently**. `src/main.py:572` trusts `127.0.0.1, 10/8, 172.16/12, 192.168/16`; `Dockerfile:40` passes `--forwarded-allow-ips 172.16.0.0/12,10.0.0.0/8`, which *excludes* the real proxy subnet and is therefore inert. The app-level list is the only effective control, it is a hard-coded literal no operator can narrow, and it spans a Docker network shared with dozens of other containers — several of which run user-supplied code by design. Any such peer can forge `X-Forwarded-For` and rotate the key of every slowapi limiter, including the 5/min login limiter guarding other tenants' panel passwords. Codex's audit note is explicit that a username-keyed limit must be **additive** to the IP-keyed one, not a replacement.
- **#194 residual (V2.4.1)** — `#269` shipped the per-principal buckets, the failed-auth budget and the default daily quota, but deferred one item: `/register` is unauthenticated RFC 7591 dynamic client registration and `cleanup_expired_tokens` deletes `OAuthCode` and `OAuthToken` rows but **never** `OAuthClient`. Production holds 18 rows and the limiter admits ~4,320 new ones per day per address. Nothing ever removes a registration that was never used.

The three are disjoint in files and in mechanism, which is why they ship as one change with three independent slices rather than three changes.

## What Changes

- **A plaintext-refusal router, in this repo's compose labels.** A higher-priority router on the `http` entrypoint for `Host(${MCP_HOSTNAME})` and the machine paths — `/mcp`, `/transfer`, `/health`, `/.well-known`, `/register`, `/token`, `/revoke` — carrying an `ipAllowList` middleware whose source range is `192.0.2.0/32` (RFC 5737 TEST-NET-1, never a real client). Traefik answers **403 with no `Location`** and forwards nothing to the app. Browser paths (`/admin`, `/authorize`) keep redirecting, because a person typing a hostname is not leaking a bearer token. The ACME HTTP-01 challenge prefix is carved out with a negated matcher so the certificate resolver answering on the `http` entrypoint keeps working. `Caddyfile.example` gets the same refusal via an `http://` site block, so the published reference deployment is not weaker than the production one. Both are host-value-free: the hostname enters only through `${MCP_HOSTNAME}`.
- **One setting for proxy trust.** `TRUSTED_PROXY_IPS` (pydantic, CSV or JSON, every entry parsed as an address or CIDR at boot, default exactly the four ranges in force today) drives `ProxyHeadersMiddleware`. The Dockerfile's `--proxy-headers --forwarded-allow-ips …` becomes `--no-proxy-headers`, so uvicorn contributes no second, silently-divergent list. The effective list is logged once at startup. Narrowing it to Traefik's address is documented as the operator's job; **giving Traefik a static IP on a dedicated backend network is host infrastructure and is out of scope** — filed as a follow-up for the owner.
- **A username-keyed failed-login budget, additive to the IP-keyed 5/min limit.** slowapi cannot do this: its `key_func` is synchronous and runs before the handler, and reading the form body there would consume the stream (`src/limiter.py` says so in as many words). So it is an in-process fixed-window budget in `src/services/rate_limits.py`, built on the same salted fixed-size slot table as the `/mcp` failed-authentication budget, keyed on the normalised submitted username. It is **not an account lockout** — see `design.md` D6 for the DoS answer. The refusal renders the **byte-identical** 401 login page, so it is not a username oracle; the only place the distinction exists is a new `panel_login_account_throttled` security event.
- **A length bound on `username_submitted`.** The login form accepts an unbounded username and `panel_login_failed` writes it straight into the security log today. It is truncated to the `users.username` column width (255) before it enters any record or any budget key.
- **Expiry of unused dynamically registered OAuth clients.** `cleanup_expired_tokens` gains a fourth predicate: delete a client that has never been used, has no live child row, and is older than `OAUTH_CLIENT_UNUSED_EXPIRY_DAYS` (default 30, `null` disables). "Never used" is a new `oauth_clients.last_used_at`, stamped whenever an authorization code or a token is issued for that client — **migration 025**, additive and nullable, backfilled from the newest surviving `oauth_tokens`/`oauth_codes` row per client. The candidate scan locks each row `FOR UPDATE` and re-checks inside the lock, so a client authorizing concurrently is never deleted out from under its own code insert.

One additive migration (025, `oauth_clients.last_used_at`). No new dependencies, no new permission, no change to quota semantics or to any filesystem algorithm.

## Capabilities

### New Capabilities

- `edge-transport-security`: machine-facing paths refuse plaintext HTTP at the proxy with a 4xx and no `Location`, without forwarding the request to the application; browser-facing paths keep redirecting; the ACME challenge prefix is exempt; the rules live in tracked repository files and name the host only through `MCP_HOSTNAME`.

### Modified Capabilities

- `request-trust`: the proxy-header trust list becomes a single validated setting with the current list as its default, and the uvicorn-level allow-list is removed so exactly one control exists.
- `api-auth-hardening`: login rate limiting keeps the 5/min per-address limit and gains an additive per-username failed-attempt budget whose refusal is indistinguishable from an ordinary failed login.
- `security-event-logging`: a bounded `panel_login_account_throttled` event, and a length bound on every caller-supplied username entering a record.
- `oauth-authorization-integrity`: dynamically registered clients that were never used and hold no live code, token or grant expire after a configurable age; the sweep cannot race an in-flight authorization.
- `schema-integrity`: migration 025 owns `oauth_clients.last_used_at` as one marked unit, with a backfill that infers use only from rows that still exist.
