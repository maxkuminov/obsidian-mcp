## 1. Slice A — the digest and the note read surface

Owns `src/services/vault.py` (the digest helper and `read_file`), `src/mcp_server/read_result.py` (the `ReadNoteResult` model and the budget accounting), the `read_note_impl` region of `src/mcp_server/tools.py`, the `read_note` wrapper in `src/mcp_server/server.py`, and `tests/test_write_precondition_digest.py`. **Everything else waits on this** — B, C and D all consume the digest helper.

- [ ] 1.1 `vault.py`: add the one digest function — `content_hash_for_bytes(data: bytes) -> str` returning `"sha256:" + hashlib.sha256(data).hexdigest()`, plus a parser that accepts `sha256:<64 hex>` or a bare `<64 hex>` (hex case-insensitive) and reports "malformed" distinctly from "mismatch". Docstring states the definition once (design D1) and states that it is deliberately not `notes_metadata.content_hash`.
- [ ] 1.2 `vault.py` `read_file()`: read the note's **bytes** once; hash those bytes; derive today's text from the same bytes (UTF-8 strict decode, then `\r\n` → `\n`, then lone `\r` → `\n` — exactly what `Path.read_text(encoding="utf-8")` produced). Return `content_hash` in the dict beside `size`/`modified`. Do **not** add a second read (design D6).
- [ ] 1.3 `read_result.py`: `ReadNoteResult.content_hash: str | None`, server-controlled, excluded from the metadata drop order and from `metadata_omissions`; account for it as a fixed 71-character allocation beside `path` in the worst-case arithmetic.
- [ ] 1.4 `tools.py` `read_note_impl`: populate `content_hash` from `note["content_hash"]` for every successful read — whole-note, section, windowed and truncated alike. Error results carry none.
- [ ] 1.5 `server.py` `read_note` docstring: the field, that it is the **whole file's** hash in every mode, that it is not a hash of `content`, and that it is the token `edit_note`/`set_frontmatter`/`write_file`/`move_note`/`delete_note` take as `expected_hash`.
- [ ] 1.6 Tests (`tests/test_write_precondition_digest.py`): the digest equals `sha256` of the file's raw bytes for LF, CRLF and lone-CR notes and for frontmatter-bearing notes; it is **not** equal to `sha256` of the response `content`; section and truncated reads return the same value as the whole-note read; the value differs from the row's `notes_metadata.content_hash` for a CRLF note; the field survives a metadata-budget drop of every other field; `read_file()`'s text output is byte-identical to `Path.read_text()` across all three terminator dialects and for a note with a BOM; the malformed/canonical hash parser matrix.

## 2. Slice B — note write preconditions

Owns the write region of `src/mcp_server/tools.py` (`_precondition_error` and its use in `edit_note_impl`, `set_frontmatter_impl`, `move_note_impl` / `_move_note_locked`, `delete_note_impl`), the five write wrappers in `src/mcp_server/server.py`, `docs/architecture/vault-tools.md`, and `tests/test_write_preconditions_notes.py`. **Starts after A merges.** Do NOT touch `read_note_impl`, `read_file_impl`, `write_file_impl`, `list_files_impl`, `read_result.py`, or `indexer.py` — they belong to A, C and D.

- [ ] 2.1 `tools.py`: one shared `_precondition_error(tool, path, incumbent_bytes, expected_hash) -> str | None` producing the malformed-input refusal and the stale refusal (naming the current hash, stating nothing was written, carrying no note content, distinct from `File changed while editing`). Design D3 has the wording.
- [ ] 2.2 `edit_note_impl`: `expected_hash: str | None = None`; evaluate immediately after `existing_bytes` is read and **before** mode dispatch, the size cap, the `dry_run` diff and every no-op branch (design D2). Applies to all four modes and to `replace_frontmatter`.
- [ ] 2.3 `set_frontmatter_impl`: same argument, evaluated immediately after `raw_bytes` is read — ahead of the defect diagnosis, the lossy refusal and the empty-`updates` no-op.
- [ ] 2.4 `delete_note_impl`: same argument; when supplied, read the incumbent through the already-open target, compare, and refuse before the pin / soft-delete rename / permanent unlink. Both `permanent` values.
- [ ] 2.5 `move_note_impl` / `_move_note_locked`: same argument, binding **`from_path`'s bytes only**, compared in the preflight before the rename and before any link rewrite; the refusal states that backlink sources are not bound.
- [ ] 2.6 Every guarded note tool reports the published file's `content_hash` in its success message (`create_note` too); `dry_run` reports none.
- [ ] 2.7 `_tracked` parameter lists gain `expected_hash` for each of the five tools.
- [ ] 2.8 `server.py`: the five signatures and docstrings, kept symmetric — the same paragraph in each, naming the two windows, saying the argument is optional, that a section write binds the whole file, and that a `move_note` precondition binds only the moved note. Correct the `edit_note` paragraph that currently says "No write tool takes an expected hash or version".
- [ ] 2.9 Tests (`tests/test_write_preconditions_notes.py`): per tool and per mode — stale → refusal naming the current hash with the file byte-identical and no `notes_metadata`/`note_links` change; omitted → today's behaviour (including the silent overwrite); matching → success; malformed → the malformed refusal; `expected_hash` on `create_note` → refused, nothing created; stale precondition beats the `dry_run` diff, the `set_frontmatter` no-op and the frontmatter-defect report; a matching precondition still hits the in-call `expected=` compare when the file changes in between (patch the point between the check and the publish) and the two messages differ; a section write with a whole-file hash refuses after an unrelated edit elsewhere; `usage_logs` records `expected_hash`.
- [ ] 2.10 `docs/architecture/vault-tools.md`: the digest definition (once, pointing at the spec), the two windows and what each covers, the per-tool table from design D4, the residuals L1/L3/L6, and the replacement of the "no write tool accepts an expected hash" paragraph that #205 tracked.

## 3. Slice C — the raw-file surface

Owns the raw-file region of `src/mcp_server/tools.py` (`_base64_payload`, `read_file_impl`, `write_file_impl`), their two wrappers in `src/mcp_server/server.py`, and `tests/test_write_preconditions_files.py`. **Starts after A merges; runs in parallel with B and D** — region-disjoint within `tools.py`, and the orchestrator owns the merge.

- [ ] 3.1 `_base64_payload`: add a `content_hash:` line to the header, above the blank line and the body.
- [ ] 3.2 `read_file_impl`: `hash_only: bool = False` returning a metadata-only result (path, bytes, mime, `content_hash`) and no content; refuse `hash_only` combined with a non-default `offset`/`limit`; `encoding` has no effect and the docstring says so. Text results are otherwise untouched.
- [ ] 3.3 `write_file_impl`: `expected_hash: str | None = None`. With `overwrite=True`, read the incumbent through the validated target (bounded by `MAX_FILE_READ_BYTES`, over-cap → refusal naming the cap), compare via the shared helper, and on a match pass those bytes as `expected=` to the publish so the in-call window closes too. With `overwrite=False` → refusal. Without the argument → no read, unchanged behaviour. Success reports the resulting `content_hash`.
- [ ] 3.4 `_tracked` parameter lists for `read_file` (`hash_only`) and `write_file` (`expected_hash`).
- [ ] 3.5 `server.py`: `read_file` and `write_file` signatures and docstrings — where a raw file's hash comes from (base64 header, `hash_only`, the write's own success line), and that a text read is deliberately unenveloped.
- [ ] 3.6 Tests (`tests/test_write_preconditions_files.py`): guarded overwrite stale/matching/malformed; `overwrite=False` + `expected_hash` refused with nothing created; unguarded overwrite performs no incumbent read (assert via the read helper); over-cap incumbent refuses naming the cap; base64 header carries the hash; `hash_only` returns no bytes; `hash_only` + `offset` refused; a text read is byte-identical to today; the reported hash of a written file matches a subsequent `read_file(hash_only=True)`.

## 4. Slice D — #154, non-finite frontmatter numbers

Owns `src/services/indexer.py` (`_sanitize_value`), the `_view_leaf` and omission-reason region of `src/mcp_server/read_result.py`, `docs/architecture/indexing-and-embeddings.md`, and `tests/test_issue_154_non_finite_frontmatter.py`. **Starts after A merges; runs in parallel with B and C.** Do not touch `ReadNoteResult`'s fields or the budget code (Slice A's), and do not touch `_scrub_frontmatter` or `_representability` at all.

- [ ] 4.1 **Pin today's behaviour first**, before changing anything: a test that a `float('nan')` in the frontmatter mapping fails the JSONB write against a real pgvector container (integration), and a test that `read_result._view_leaf` today renders `str(value)`. Record what was observed in the test's docstring — the design's account of today is reasoned from code, and this is where it becomes fact.
- [ ] 4.2 `indexer.py` `_sanitize_value`: a non-finite float becomes its YAML token (`.nan`, `.inf`, `-.inf`) at that boundary, ahead of the passthrough branch for finite floats. Comment explains why here and not at the parse (design D10).
- [ ] 4.3 `read_result.py` `_view_leaf`: the same YAML tokens instead of `str(value)`; add the coercion's reason code and emit a `metadata_omissions` entry naming `frontmatter` and pointing at `frontmatter_yaml`. The view is **not** omitted for this reason.
- [ ] 4.4 Tests (`tests/test_issue_154_non_finite_frontmatter.py`): a note with `x: .nan`, `a: .inf`, `b: -.inf` indexes and the pass commits (integration, real JSONB); consecutive passes both complete and `content_hash` advances; `read_note` returns the tokens, both renderings agree, no `NaN`/`Infinity` appears in either, no protocol error; `metadata_omissions` records the coercion; **`set_frontmatter` setting an unrelated key on such a note leaves `x: .nan` byte-identical**; `keyword_search(frontmatter=…)` matches the stored token.
- [ ] 4.5 `docs/architecture/indexing-and-embeddings.md`: the boundary rule — the scrub keeps the float because YAML and Python both render it, each JSON boundary coerces to the YAML token, the index pass can never die of it, and `set_frontmatter` round-trips the original scalar. Cross-reference the representability-boundary section in `vault-tools.md` without duplicating it.
