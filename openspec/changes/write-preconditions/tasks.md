Merge order is **A → (B ∥ D) → C**. `tools.py` and `server.py` are touched by A, B and C, so they are region-owned and sequenced rather than fanned out: the shared precondition helper lives in A so that neither B nor C owns a dependency of the other, and C follows B because both edit the same two files.

## 1. Slice A — refusal contract, digest, config lever, and the note read surface

Owns `src/services/refusals.py`, `src/services/vault.py`, `src/config.py`, `src/mcp_server/read_result.py`, the **shared helper region and `read_note_impl`** of `src/mcp_server/tools.py`, the `read_note` wrapper in `src/mcp_server/server.py`, and `tests/test_write_precondition_digest.py`. **Everything else waits on this.**

- [ ] 1.1 `src/services/refusals.py`: if the sibling `mcp-rate-limits` change has already landed it, add the four codes to its closed set; if not, **create it with the identical contract** — a `Refusal` carrying `code` plus per-code fields, importing nothing from the app, and one renderer appending a final line-initial single-line `MCP-REFUSAL {…}` sentinel to the tool's prose, absent-not-null for unused fields. Codes: `stale_precondition` (`path`, `current_hash`, `nothing_written`), `no_incumbent`, `malformed_precondition`, `precondition_required` (`current_hash` only where the caller already read the incumbent). No retry delay on any of them.
- [ ] 1.2 `vault.py`: the one digest function — `content_hash_for_bytes(data: bytes) -> str` returning `"sha256:" + hashlib.sha256(data).hexdigest()` — and a parser accepting **only** `sha256:<64 lowercase hex>`, reporting malformed distinctly from mismatch. Docstring states the definition once (design D1) and states that it is deliberately not `notes_metadata.content_hash`.
- [ ] 1.3 `vault.py` `read_file()`: read the note's **bytes** once; hash those bytes; derive today's text from the same bytes (UTF-8 strict decode, then `\r\n` → `\n`, then lone `\r` → `\n` — exactly what `Path.read_text(encoding="utf-8")` produced). Return `content_hash` in the dict beside `size`/`modified`. Do **not** add a second read (design D6).
- [ ] 1.4 `vault.py`: the shared non-finite token helper — canonical `.nan` / `.inf` / `-.inf` for any non-finite float, whatever the source spelling — that slices A and D both consume, plus the title coercion in `read_file()` that uses it (`read_note` and the panel inherit it).
- [ ] 1.5 `config.py`: `WRITE_PRECONDITION_REQUIRED`, a `Settings` boolean defaulting to **false**, with the comment that it is a deployment lever and never a per-call one.
- [ ] 1.6 `read_result.py`: `ReadNoteResult.content_hash: str | None`, server-controlled, excluded from the metadata drop order and from `metadata_omissions`, accounted for as a fixed 71-character allocation beside `path` in the worst-case arithmetic; and a new `metadata_coercions` list field of the same shape as `metadata_omissions` (field, reason code, where to read the note's own form) for retained-but-altered values.
- [ ] 1.7 `tools.py` (shared region): `_precondition_error(tool, path, incumbent_bytes | None, expected_hash) -> str | None` producing the four typed refusals through `refusals.py`, plus the required-mode check reading `WRITE_PRECONDITION_REQUIRED`. One helper, so B and C both consume A rather than each other.
- [ ] 1.8 `tools.py` `read_note_impl`: populate `content_hash` from `note["content_hash"]` for every successful read — whole-note, section, windowed and truncated alike. Error results carry none.
- [ ] 1.9 `server.py` `read_note` docstring: the field, that it is the **whole file's** hash in every mode, that it is not a hash of `content`, that `frontmatter_yaml` is authoritative but LF-normalized and `read_file` is the byte-exact route, and that the hash is the token the write tools take as `expected_hash`.
- [ ] 1.10 Tests (`tests/test_write_precondition_digest.py`): the digest equals `sha256` of the file's raw bytes for LF, CRLF and lone-CR notes and for frontmatter-bearing notes; it is **not** equal to `sha256` of the response `content`; section and truncated reads return the same value as the whole-note read; the value differs from the row's `notes_metadata.content_hash` for a CRLF note; the field survives a metadata-budget drop of every other field; `read_file()`'s text output is byte-identical to `Path.read_text()` across all three terminator dialects and for a note with a BOM; the parser matrix (canonical accepted; bare hex, uppercase hex, whitespace, wrong length, unknown prefix each malformed); the sentinel renders as one line and survives being embedded in a longer prose result.

## 2. Slice B — note write preconditions

Owns the note-write region of `src/mcp_server/tools.py` (`create_note_impl`, `edit_note_impl`, `set_frontmatter_impl`, `move_note_impl` / `_move_note_locked`, `delete_note_impl`), the six write wrappers in `src/mcp_server/server.py`, `docs/architecture/vault-tools.md`, and `tests/test_write_preconditions_notes.py`. **Starts after A merges; runs in parallel with D.** Do NOT touch `read_note_impl`, the shared helper, `read_file_impl`, `write_file_impl`, `vault.py`, `read_result.py` or `indexer.py`.

- [ ] 2.1 `edit_note_impl`: `expected_hash: str | None = None`; evaluate through A's helper immediately after `existing_bytes` is read and **before** mode dispatch, the size cap, the `dry_run` diff and every no-op branch (design D2). All four modes and `replace_frontmatter`.
- [ ] 2.2 `set_frontmatter_impl`: same argument, evaluated immediately after `raw_bytes` is read — ahead of the defect diagnosis, the lossy refusal and the empty-`updates` no-op.
- [ ] 2.3 `create_note_impl`: accepts `expected_hash` and answers `no_incumbent` **before any filesystem work** — the signature must not reject it, or the caller gets a protocol error instead of the contract. Exempt from required mode.
- [ ] 2.4 `delete_note_impl`: same argument; when supplied, read the incumbent through the already-open target, compare, and refuse before the pin / soft-delete rename / permanent unlink. Both `permanent` values. Reports no `content_hash` on success.
- [ ] 2.5 `move_note_impl` / `_move_note_locked`: same argument, binding **`from_path`'s bytes only**, compared in the preflight before the rename and before any rewrite; the refusal prose states that backlink sources are not bound. Success reports the **destination's** hash (for `rewrite_links=True`, the moved note's own post-rewrite bytes).
- [ ] 2.6 Success results: `create_note`, `edit_note` (not `dry_run`), `set_frontmatter` (not a no-op) and `move_note` report the published file's `content_hash`. Update the existing tests that assert on these strings — the compatibility claim is about mutation semantics, not result text.
- [ ] 2.7 Required mode wired through each of the five enforceable tools via A's helper; `create_note` exempt.
- [ ] 2.8 `_tracked` parameter lists gain `expected_hash` for all six tools.
- [ ] 2.9 `server.py`: the six signatures and docstrings, kept symmetric — one shared paragraph naming the two windows, the optionality, the canonical hash form, that a section write binds the whole file, that a `move_note` precondition binds only the moved note and its success hash is the destination's. Correct the `edit_note` paragraph that currently says "No write tool takes an expected hash or version".
- [ ] 2.10 Tests (`tests/test_write_preconditions_notes.py`): per tool and per mode — stale → `stale_precondition` naming the current hash with the file byte-identical and no `notes_metadata`/`note_links` change; omitted → today's behaviour including the silent overwrite; matching → success; malformed (bare hex, uppercase, wrong length) → `malformed_precondition`; `create_note` with a hash → `no_incumbent`, nothing created, no protocol error; stale beats the `dry_run` diff, the `set_frontmatter` no-op and the frontmatter-defect report; a matching precondition still hits the in-call `expected=` compare when the file changes in between and the two refusals differ; a section write with a whole-file hash refuses after an unrelated edit elsewhere; `move_note(rewrite_links=True)`'s reported hash matches the destination file and binds a following `edit_note`; required mode refuses each enforceable tool and lets `create_note` through; `usage_logs` records `expected_hash` and records the refusal row.
- [ ] 2.11 `docs/architecture/vault-tools.md`: the digest definition (once, pointing at the spec), the two windows, the per-tool table from design D4 including the result column, the typed refusal codes, and the residuals L1/L3/L6/L10/L11 — replacing the "no write tool accepts an expected hash" paragraph #205 tracked.

## 3. Slice C — the raw-file surface

Owns `_base64_payload`, `read_file_impl` and `write_file_impl` in `src/mcp_server/tools.py`, their two wrappers in `src/mcp_server/server.py`, the `write_bytes_at` / `write_bytes` signatures in `src/services/vault.py`, and `tests/test_write_preconditions_files.py`. **Starts after B merges** (same two files) **and after D** (same file in `vault.py`, different region).

- [ ] 3.1 `vault.py`: `write_bytes_at(…, expected: bytes | None = None)` and `write_bytes(…, expected=None)` forwarding to `_atomic_write_at` — today the raw-byte path cannot reach the comparison at all. Default `None` keeps every existing call site unchanged; regression test covers the single-shot `write_bytes` caller.
- [ ] 3.2 `_base64_payload`: add a `content_hash:` line to the header, above the blank line and the body.
- [ ] 3.3 `read_file_impl`: `hash_only: bool = False` returning a metadata-only result (path, bytes, MIME, `content_hash`) and no content. Precedence: validate `encoding` first, then refuse `hash_only` combined with a non-default `offset`/`limit`, then the existing range checks; a valid `encoding` has no effect under `hash_only` and the docstring says so. Text results otherwise untouched.
- [ ] 3.4 `write_file_impl`: `expected_hash: str | None = None`. With `overwrite=True` on an existing file, read the incumbent through the validated target (bounded by `MAX_FILE_READ_BYTES`, over-cap → refusal naming the cap), compare via A's helper, and on a match pass those bytes as `expected=` to the publish. With `overwrite=False`, or `overwrite=True` on a **missing** path, → `no_incumbent`, nothing created. Without the argument → no read, unchanged behaviour. Required mode applies to `overwrite=True` only. Success reports the resulting `content_hash`.
- [ ] 3.5 `_tracked` parameter lists for `read_file` (`hash_only`) and `write_file` (`expected_hash`).
- [ ] 3.6 `server.py`: `read_file` and `write_file` signatures and docstrings — where a raw file's hash comes from (base64 header, `hash_only`, the write's own success line), the argument precedence, that a text read is deliberately unenveloped, and that `read_file` is the byte-exact route for a frontmatter block.
- [ ] 3.7 Tests (`tests/test_write_preconditions_files.py`): guarded overwrite stale/matching/malformed; `overwrite=False` + hash and `overwrite=True` on an absent path → `no_incumbent` with nothing created; unguarded overwrite performs no incumbent read; over-cap incumbent refuses naming the cap; base64 header carries the hash; `hash_only` returns no bytes; `hash_only` + `offset` refused; invalid `encoding` refused ahead of `hash_only`; a text read byte-identical to today; the reported hash of a written file matches a subsequent `read_file(hash_only=True)`; `write_bytes` with a stale `expected` refuses and with none behaves as today.

## 4. Slice D — #154, non-finite frontmatter numbers

- [ ] 4.1 **Pin today's behaviour first**, before changing anything: an integration test that a `float('nan')` in the frontmatter mapping fails the JSONB write against a real pgvector container, and a unit test that `_view_leaf` today renders `str(value)` while `_note_title` yields `nan`. Record what was observed in the test docstrings — the design's account of today is reasoned from code, and this is where it becomes fact.
- [ ] 4.2 `indexer.py`: **split `_sanitize_value`** into a JSONB sanitiser and a title coercion, both over A's shared token helper, so the two questions stop sharing one return value. The JSONB sanitiser renders a non-finite float as its canonical YAML token ahead of the finite-float passthrough; the title coercion renders the same token. Comment explains why here and not at the parse (design D10).
- [ ] 4.3 `read_result.py` `_view_leaf`: A's shared token helper instead of `str(value)`; add the coercion's reason code and emit a **`metadata_coercions`** entry naming `frontmatter` and pointing at `frontmatter_yaml`. - [ ] 4.4 Tests (`tests/test_issue_154_non_finite_frontmatter.py`): a note with `x: .nan`, `a: .inf`, `b: -.inf` indexes and the pass commits (integration, real JSONB); the note's body is edited between two passes and `content_hash` advances with both passes completing; alternate spellings (`.NaN`, `.INF`, `+.inf`) store and render canonically; `read_note` returns the tokens, both renderings agree, no `NaN`/`Infinity` in either, no protocol error; `metadata_coercions` records it and `metadata_omissions` does not; **cross-tool title agreement** — `notes_metadata.title`, `read_note`'s `title` and the panel's note view all show `.nan` for `title: .nan`, and an ordinary-title fixture corpus is byte-identical to today; **`set_frontmatter` setting an unrelated key on such a note leaves `x: .nan` byte-identical**; `keyword_search(frontmatter=…)` matches the stored token.
- [ ] 4.5 `docs/architecture/indexing-and-embeddings.md`: the boundary rule — the scrub keeps the float because YAML and Python both render it, each JSON boundary and the title coercion use one shared canonical token helper, the index pass can never die of it, `set_frontmatter` round-trips the original scalar, and the split of `_sanitize_value` into two named questions.
