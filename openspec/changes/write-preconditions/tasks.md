Merge order is **A → (B ∥ D) → C**. `tools.py` and `server.py` are touched by A, B and C, so they are region-owned and sequenced rather than fanned out: the shared precondition helper lives in A so that neither B nor C owns a dependency of the other, and C follows B because both edit the same two files.

## 1. Slice A — refusal contract, digest, config lever, and the note read surface

Owns `src/services/refusals.py`, `src/services/vault.py`, `src/config.py`, `src/mcp_server/read_result.py`, the **shared helper region and `read_note_impl`** of `src/mcp_server/tools.py`, the `read_note` wrapper in `src/mcp_server/server.py`, and `tests/test_write_precondition_digest.py`. **Everything else waits on this.**

- [x] 1.1 `src/services/refusals.py`: if the sibling `mcp-rate-limits` change has already landed it, add the six codes to its closed set; if not, **create it with the identical contract** — a `Refusal` carrying `code` plus per-code fields, importing nothing from the app, and one renderer appending a final line-initial single-line `MCP-REFUSAL {…}` sentinel to the tool's prose, absent-not-null for unused fields. Codes: `stale_precondition` (`path`, `current_hash`, `nothing_written`), `concurrent_write` (existing prose unchanged, sentinel appended), `no_incumbent`, `malformed_precondition`, `precondition_unavailable` (`cap_name`, `cap_bytes`), `precondition_required` (`current_hash` only where the caller already read the incumbent). No retry delay on any of them.
- [x] 1.2 `vault.py`: the one digest function — `content_hash_for_bytes(data: bytes) -> str` returning `"sha256:" + hashlib.sha256(data).hexdigest()` — and a parser accepting **only** `sha256:<64 lowercase hex>`, reporting malformed distinctly from mismatch. Docstring states the definition once (design D1) and states that it is deliberately not `notes_metadata.content_hash`.
- [x] 1.3 `vault.py` `read_file()`: read the note's **bytes** once; hash those bytes; derive today's text from the same bytes (UTF-8 strict decode, then `\r\n` → `\n`, then lone `\r` → `\n` — exactly what `Path.read_text(encoding="utf-8")` produced). Return `content_hash` in the dict beside `size`/`modified`. Do **not** add a second read (design D6).
- [x] 1.4 `vault.py`: the shared non-finite token helper — canonical `.nan` / `.inf` / `-.inf` for any non-finite float, whatever the source spelling, applied to mapping **keys** as well as values — that slices A and D both consume; plus the shared title rule (design D10b: the indexer's `_note_title` semantics, container stringification and the 512-character bound included, with the non-finite exception) exposed once and adopted by `read_file()`'s title coercion, which `read_note` and the panel inherit.
- [x] 1.5 `config.py`: `WRITE_PRECONDITION_REQUIRED`, a `Settings` boolean defaulting to **false**, with the comment that it is a deployment lever and never a per-call one.
- [x] 1.6 `read_result.py`: `ReadNoteResult.content_hash: str | None`, server-controlled, excluded from the metadata drop order and from `metadata_omissions`, accounted for as a fixed 71-character allocation beside `path` in the worst-case arithmetic; and a new `metadata_coercions` list field of the same shape as `metadata_omissions` (field, reason code, where to read the note's own form) for retained-but-altered values.
- [x] 1.7 `tools.py` (shared region): **two** helpers, not one. `_precondition_syntax_error(tool, expected_hash) -> str | None` is a pure function of the argument, called at each tool's **entry — before path resolution, the leaf check and any read** — so `malformed_precondition` wins over not-found, over a symlinked leaf and over the size cap. `_precondition_error(tool, path, incumbent_bytes | None, expected_hash, …) -> str | None` implements the rest of the ladder — syntax, no-incumbent, unavailable (with the cap's name and value), required mode, comparison — and renders each through `refusals.py`, with the **per-code remedy prose** from design D3 (each code says what resolves *that* code — `no_incumbent` says "call again without `expected_hash`", `malformed_precondition` names the canonical form, `precondition_unavailable` names the cap and that only an operator can raise it); plus the shared rendering of the in-call conflict as `concurrent_write` (prose unchanged, sentinel appended) for the tools that catch it. Both helpers live in A, so B and C consume A rather than each other.
- [x] 1.7a `tools.py` (shared region): one bounded-incumbent reader used by every guarded tool — `fstat` the descriptor the tool already holds, compare against that tool's own cap (`MAX_NOTE_BYTES` for the note tools, `MAX_FILE_READ_BYTES` for the raw-file tools), then read through **that same descriptor**; over cap → `precondition_unavailable` carrying the cap's name and value when a hash was supplied or required mode is on, and otherwise **no refusal at all**: the call proceeds as today and reports no result hash.
- [x] 1.8 `tools.py` `read_note_impl`: populate `content_hash` from `note["content_hash"]` for every successful read — whole-note, section, windowed and truncated alike. Error results carry none.
- [x] 1.9 `server.py` `read_note` docstring: the field, that it is the **whole file's** hash in every mode, that it is not a hash of `content`, that `frontmatter_yaml` is authoritative but LF-normalized and `read_file` is the byte-exact route, and that the hash is the token the write tools take as `expected_hash`.
- [x] 1.10 Tests (`tests/test_write_precondition_digest.py`): the digest equals `sha256` of the file's raw bytes for LF, CRLF and lone-CR notes and for frontmatter-bearing notes; it is **not** equal to `sha256` of the response `content`; section and truncated reads return the same value as the whole-note read; the value differs from the row's `notes_metadata.content_hash` for a CRLF note; the field survives a metadata-budget drop of every other field; `read_file()`'s text output is byte-identical to `Path.read_text()` across all three terminator dialects and for a note with a BOM; the parser matrix (canonical accepted; bare hex, uppercase hex, whitespace, wrong length, unknown prefix each malformed); the precedence ladder exercised directly against the helpers (malformed beats no-incumbent beats unavailable beats required beats comparison), including that the syntax helper needs no path and no descriptor; the sentinel renders as one line, carries `cap_name`/`cap_bytes` for `precondition_unavailable`, omits absent fields, and survives being embedded in a longer prose result.

- [x] 2.1 `edit_note_impl`: `expected_hash: str | None = None`; evaluate through A's helper immediately after `existing_bytes` is read and **before** mode dispatch, the size cap, the `dry_run` diff and every no-op branch (design D2). All four modes and `replace_frontmatter`.

- [x] 2.6 Success results: `create_note`, `edit_note` (not `dry_run`), `set_frontmatter` (not a no-op) and `move_note` report the published file's `content_hash`; `delete_note` reports none. - [x] 2.8 `_tracked` parameter lists gain `expected_hash` for all six tools.

Correct the `edit_note` paragraph that currently says "No write tool takes an expected hash or version".

## 3. Slice C — the raw-file surface

Owns `_base64_payload`, `read_file_impl`, `write_file_impl` and `delete_file_impl` in `src/mcp_server/tools.py`, their three wrappers in `src/mcp_server/server.py`, the `write_bytes_at` / `write_bytes` signatures in `src/services/vault.py`, and `tests/test_write_preconditions_files.py`. **Starts after B merges** (same two files) **and after D** (same file in `vault.py`, different region).

- [ ] 3.1 `vault.py`: `write_bytes_at(…, expected: bytes | None = None)` and `write_bytes(…, expected=None)` forwarding to `_atomic_write_at` — today the raw-byte path cannot reach the comparison at all. Default `None` keeps every existing call site unchanged; regression test covers the single-shot `write_bytes` caller.
- [ ] 3.1a Every tool in this slice calls A's `_precondition_syntax_error` at its **entry**, ahead of path validation and the leaf check, and reads its incumbent through A's bounded reader (`MAX_FILE_READ_BYTES`, `fstat` then a read through the same descriptor).
- [ ] 3.2 `_base64_payload`: add a `content_hash:` line to the header, above the blank line and the body — **and render the `path` field as a quoted JSON string**, uniformly for every path, so a filename carrying a newline, CR or colon cannot inject a header line into the region this change asks callers to trust (design D7, L12). The `hash_only` result uses the same encoding.
- [ ] 3.3 `read_file_impl`: `hash_only: bool = False` returning a metadata-only result (path, bytes, MIME, `content_hash`) and no content. Precedence: validate `encoding` first, then refuse `hash_only` combined with a window — decided **by value**, `offset != 0 or limit is not None`, never by whether the argument was passed — then the existing range checks; a valid `encoding` has no effect under `hash_only` and the docstring says so. Text results otherwise untouched.
- [ ] 3.4 `write_file_impl`: `expected_hash: str | None = None`. With `overwrite=True` on an existing file, read the incumbent through the validated target (bounded by `MAX_FILE_READ_BYTES`, over-cap → refusal naming the cap), compare via A's helper, and on a match pass those bytes as `expected=` to the publish. With `overwrite=False`, or `overwrite=True` on a **missing** path, → `no_incumbent`, nothing created. Without the argument → no read, unchanged behaviour. Required mode applies to `overwrite=True` only. Success reports the resulting `content_hash`.
- [ ] 3.4a `delete_file_impl`: `expected_hash: str | None = None` in **both** modes; when supplied (or required), read the incumbent through the tool's own anchored beneath-root lookup, compare via A's helper, and refuse **before** the `.trash` rename and before the unlink. Success reports no `content_hash`.
- [ ] 3.5 `_tracked` parameter lists for `read_file` (`hash_only`) and `write_file` / `delete_file` (`expected_hash`).
- [ ] 3.6 `server.py`: `read_file`, `write_file` and `delete_file` signatures and docstrings — where a raw file's hash comes from (base64 header, `hash_only`, the write's own success line), the argument precedence, that a text read is deliberately unenveloped, and that `read_file` is the byte-exact route for a frontmatter block.
- [ ] 3.7 Tests (`tests/test_write_preconditions_files.py`): guarded overwrite stale/matching/malformed; `overwrite=False` + hash and `overwrite=True` on an absent path → `no_incumbent` with nothing created; **malformed beats both of those and beats over-cap**; unguarded overwrite performs no incumbent read; over-cap incumbent → `precondition_unavailable` carrying the cap's name and value; the same case under required mode with no hash → `precondition_unavailable`, not `precondition_required`; the same case **unguarded with required mode off → the write succeeds as today with no result hash**; a malformed hash beating not-found, a symlinked leaf and the size cap on `write_file` and `delete_file`; base64 header carries the hash; **paths containing a newline, a CR, a colon and a blank line render as one quoted JSON string in both the base64 header and the `hash_only` result, with no injected field**; `hash_only` returns no bytes; `hash_only` + `offset=0` succeeds while `hash_only` + `limit=1` is refused; invalid `encoding` refused ahead of `hash_only`; a text read byte-identical to today; the reported hash of a written file matches a subsequent `read_file(hash_only=True)`; `delete_file` stale / matching / required in both `permanent` modes, asserting no `.trash` entry on a refusal; `write_bytes` with a stale `expected` refuses and with none behaves as today.
