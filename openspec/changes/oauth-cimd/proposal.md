Refs #357.

## Why

MCP 2026-07-28 deprecates RFC 7591 Dynamic Client Registration in favour of OAuth Client ID Metadata Documents (CIMD, SEP-991, `draft-ietf-oauth-client-id-metadata-document-00`). The lifecycle policy keeps a deprecated feature for at least twelve months, so DCR stays until at least 2027-07-28. Anthropic's connector documentation says Claude "selects CIMD only when your authorization server metadata advertises both `"client_id_metadata_document_supported": true` and `"none"` in `token_endpoint_auth_methods_supported`… If either is missing, Claude falls back to DCR". It also says "DCR causes Claude to register a new client on every fresh connection, which can result in very large numbers of registered clients", which is the residue #194's sweep exists to delete. This authorization server advertises `none` already but not the CIMD flag, so every connection today takes the DCR fallback. Claude Code cannot connect at all: its CIMD declares `http://localhost/callback` and `http://127.0.0.1/callback`, and `/register` accepts only `https` redirect URIs.

## What Changes

- **AS metadata** gains `client_id_metadata_document_supported: true` (only while `OAUTH_CIMD_ENABLED`) and `authorization_response_iss_parameter_supported: true`. It keeps `none` in `token_endpoint_auth_methods_supported` and keeps `registration_endpoint`, because DCR remains the fallback.
- **URL detection.** At `/authorize` (GET and POST), any `client_id` beginning `https://` is a CIMD client identifier. It is never looked up as a DCR id, since DCR ids are 32 hex characters. The URL must be ≤ 2,048 ASCII characters, already in the canonical form the hardened fetch would request (byte-equal), with a path other than `/`, no dot segments, no fragment, no userinfo, and port 443 or 8443. At `/token` and `/revoke`, the caller's `client_id` matches a CIMD client row when it byte-equals the row's stored URL. **The token endpoint never fetches.**
- **Hardened fetch** reuses `src/services/transfer.py`'s guarded fetch: `trust_env=False`, **no redirects** (`max_redirects=0`), a 10 s deadline, a 64 KiB cap, identity encoding only, and the transfer SSRF deny list with every resolved address checked and the connection pinned to the validated address. Fetches are bounded by a per-address budget (`OAUTH_CIMD_FETCHES_PER_ADDRESS_PER_MINUTE`, default 10), a process-wide cap of 4 in flight, single-flight per URL, and a 30 s per-URL cooldown after a failure. A cache hit spends nothing.
- **Validation.** The document must be a JSON object with `client_id` byte-equal to the URL and a non-empty `client_name` (≤ 255) and `redirect_uris` (1–20, each ≤ 2,048). Each redirect URI is either `https` with a resolvable ASCII host (the DCR rule) or `http` to exactly `localhost`, `127.0.0.1` or `[::1]`. `token_endpoint_auth_method` must be absent or `none`. A document carrying `client_secret` or `client_secret_expires_at` is refused. `grant_types`/`response_types`, when present, must admit `authorization_code`/`code`. `scope`, when present, must name `read` or `readwrite`.
- **Redirect matching** is exact, with one exception: a registered loopback `http` URI matches a request URI with the same host literal, path and query on **any** port (RFC 8252 §7.3; also applied to `localhost`, as Claude Code requires). The code stores the exact requested URI, so `/token`'s exact comparison is unchanged.
- **Cache.** Only validated documents are cached, keyed by the exact URL, for the response's `max-age` clamped to `OAUTH_CIMD_CACHE_MAX_SECONDS` (default and ceiling 86,400). `no-store`/`no-cache` means not cached, and a missing header means 300 s. The cache is bounded LRU and in-process (the `--workers 1` contract). A failed fetch is never cached as a document. The cooldown is the bounded negative cache.
- **Pinning.** The consent POST refuses when the validated projection of the document differs from the one the GET rendered (its SHA-256 travels in the signed consent state). The code row then pins everything the exchange depends on: the exact redirect URI and the clamped scope. Auth method is always `none`. A document that changes after consent cannot change what the code redeems for.
- **Synthetic client row** (migration **036**: `oauth_clients.client_id_metadata_url` plus a shape CHECK). The row is created or refreshed only on a consent **approve**, in the code's transaction, with `client_id = "cimd_" + sha256(url ‖ owner)[:59]`. That gives **one row per (URL, user)**, so grants, #325 lineage, `grant_issued_at`, `last_used_at`, usage attribution, the panel's per-user listing, the cascading Delete and #68's cross-user rule keep their meaning unchanged. The row carries no secret and `token_endpoint_auth_method = 'none'`.
- **Sweep rule for CIMD rows.** A CIMD row is deleted when it holds no code and no token row of any state and its `last_used_at` is older than `OAUTH_CLIENT_UNUSED_EXPIRY_DAYS`, whether or not it is bound to a user. It uses the same `SKIP LOCKED` and in-lock re-read protocol and the same `null` kill switch. A CIMD row is therefore never swept while any grant row references it, and it is re-derived from the document at the next consent.
- **Consent page.** For a CIMD client, the **host of the `client_id` URL** is the application identity. The self-asserted `client_name` is not rendered on the consent page. The full client identifier URL and the destination host stay. An all-loopback destination gets an extra warning. The standing notice states what the server verifies (that the document is published at that host) and what it does not (who operates it). The consent page's `form-action` gains `http://localhost:*` and `http://127.0.0.1:*`, because the 302 to a loopback callback is a form-submission hop.
- **RFC 9207 / RFC 8707.** Every redirect from `POST /authorize` (approve and deny) carries `iss=<issuer>`. A `resource` parameter at `/authorize` or `/token` is accepted only when it names this server's resource (`{base}/mcp` or `{base}`, with or without one trailing slash). Anything else is refused `invalid_target`. Absence is accepted. This applies to DCR clients too (**BREAKING** for any client that sends a foreign `resource`).
- **Events.** A new `oauth_client_registration_path` (INFO) is emitted for both kinds: `registration_kind` `dcr` on `/register`, and `cimd` on the approve that created or refreshed a row. CIMD refusals at `/authorize` are `oauth_authorize_refused` with `reason` `client_metadata.<sub>` and a new `cimd_host` field. The response is a constant `invalid_client` 400 that does not say why.
- **Panel.** The OAuth page marks CIMD rows, shows the client identifier URL and its host, and labels `client_name` as self-described.
- **Settings:** `OAUTH_CIMD_ENABLED` (true), `OAUTH_CIMD_CACHE_MAX_SECONDS` (86400, 0–86400), and `OAUTH_CIMD_FETCHES_PER_ADDRESS_PER_MINUTE` (10, 1–120). All go in README and `.env.example`.

## Capabilities

### New Capabilities

- `oauth-client-metadata-documents`: URL detection and canonical form; the hardened fetch and its budgets; document validation; the cache and cooldown; loopback redirect matching; consent-to-code pinning; the synthetic per-(URL, user) row, its migration and its sweep rule; client-id matching at `/token` and `/revoke`; AS metadata; RFC 9207 `iss`; RFC 8707 `resource`; the panel display; the settings.

### Modified Capabilities

- `oauth-authorization-integrity`: MODIFIED "The consent screen SHALL identify the client it is asking the user to trust" and "The consent screen SHALL state unconditionally that clients register themselves and are not verified" (the CIMD identity block and notice).
- `panel-content-security-policy`: MODIFIED "The consent page's form-action SHALL be 'self' https: and every other page's SHALL be 'self'" (adds the two loopback sources).
- `security-event-logging`: ADDED the `oauth_client_registration_path` event, the `client_metadata.*` refusal reasons and the `registration_kind` / `cimd_host` fields.
