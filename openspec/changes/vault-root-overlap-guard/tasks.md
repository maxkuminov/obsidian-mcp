## 1. The checks, the snapshot, and the gate — `src/services/vault_overlap.py`, `src/services/vault.py`, `src/config.py`, `tests/conftest.py`, `tests/test_vault_root_overlap.py`

- [ ] 1.1 Root observation: open one root as `O_RDONLY | O_DIRECTORY | O_CLOEXEC` and return `(fd, st_dev, st_ino, realpath, canonical_assignment)` taken in one moment — the real path bound to the descriptor, the way `observe_root_facts` does it, never taken from the assignment string. Descriptors closed on every exit path. A failure returns the `errno`, not an exception.
- [ ] 1.1a **Bounded:** each root's observation runs in `asyncio.to_thread` under `VAULT_ROOT_OBSERVE_TIMEOUT_SECONDS` (new setting in `src/config.py`, default **10**). Expiry is a verdict, not an exception — that user gets `root_unexaminable(timeout)`, a reason value distinct from an `errno` because a hung mount and a missing directory are different problems — and the detection proceeds to the next root. Without this the lifespan's synchronous first detection does not return on a network- or FUSE-backed root and the panel is unavailable during the incident it exists to report. Document at the call site that the deadline abandons the *wait*, not the syscall: the thread stays parked until the filesystem answers (limitation L4).
- [ ] 1.2 **Check 1 — identity:** `(st_dev, st_ino)` equality of the two descriptors.
- [ ] 1.3 **Check 2 — containment:** component-wise ancestor test over the two canonical real paths, both directions. **No string prefix comparison anywhere** — `/vaults/team` must not be an ancestor of `/vaults/team-2`.
- [ ] 1.4 The predicate takes the two **canonical assignment strings** alongside the descriptors and returns the relation found — `identical`, `contains`, `contained_by`, `mount_graft`, or `None` — so a caller can select the exact-duplicate wording for an equal pair instead of describing it as a containment.
- [ ] 1.5 Reason types: `Overlap(peer_user_id, peer_username, peer_assignment, relation)` with `relation` in {`identical`, `contains`, `contained_by`}, and `RootUnexaminable(cause)` where `cause` is an `errno` or `timeout`. An unopenable root is **not** an overlap and names no peer.
- [ ] 1.6 Each snapshot entry carries the facts **as observed at detection time** — the subject's username and canonical assignment, the peer's for an overlap, and the detection timestamp — immutable in the snapshot. Every operator surface renders these and re-reads no `users` row, so the pair stays nameable after the operator edits or deletes one of them; the surfaces label them "as at last check". Resolving names at render time is the shape that blanks the display exactly when the operator acts on the condition.
- [ ] 1.7 `detect_and_publish(session_factory)`: enumerate active users holding an assignment, observe each root once, run the pairwise checks, build the reason mapping, and **publish it atomically** — one immutable object swapped in with a single assignment, so no reader sees a half-built snapshot. Issues no database write. Returns the published snapshot.
- [ ] 1.8 **Serialize the whole operation under one process-global `asyncio.Lock`** — observation, the checks *and* the publication inside the same critical section, not the publication alone. The entry points call detection before taking `index_pass_lock` (correctly — it must not wait behind the pass it gates), so a tick and a panel reindex overlap trivially; without this, a detection stalled on a slow root publishes its own **empty** result over a newer quarantine and re-admits both tenants. A caller that finds a detection in flight waits for it.
- [ ] 1.9 **Monotonic publication:** each snapshot carries a sequence number assigned when its detection begins, taken under the same lock, and publication drops a snapshot whose sequence is not greater than the published one. The lock is the mechanism; the sequence is the invariant, and it is what survives a future caller that publishes without taking the lock.
- [ ] 1.10 Snapshot lifecycle: tri-state (never published / published-empty / published-with-reasons). A detection that raises **after** a snapshot exists retains the previous snapshot and logs at ERROR; it MUST NOT clear it back to never-published. Sandbox mode publishes an empty snapshot without touching the filesystem.
- [ ] 1.11 `VaultRootOverlap(RuntimeError)`, `VaultRootUnexaminable(RuntimeError)` and `VaultRootNotReady(RuntimeError)`, plus the one wording for each agent-facing refusal (naming no other user, no other path, no note path). Subclassing `RuntimeError` is load-bearing: every existing `except RuntimeError` around `_vault_root` keeps failing closed unchanged.
- [ ] 1.12 `_vault_root` reads the published snapshot **before** the request snapshot and raises the matching type. The lookup is refuse-only: no session, no statement, no syscall, and it cannot admit a caller the rest of the gate would refuse. Never consulted for `user_id is None`.
- [ ] 1.13a **`tests/conftest.py`:** an autouse fixture that publishes an **empty** snapshot before each test and resets the module state after it, so the readiness refusal does not turn every existing multi-user test into a vault-unavailable failure. Detector-entry tests opt *in* to the never-published state explicitly (a fixture that clears it), rather than the suite depending on import order. Also export a helper to publish a synthetic snapshot so slices 2-6 can drive the quarantined paths without running a detection.
- [ ] 1.13 Export the wording helper the assignment refusal needs, so slice 2 does not re-implement the relation-to-message mapping.
- [ ] 1.14 Tests: identity via symlink and via a second pathname for one directory; ancestor and descendant both directions; siblings accepted; `/vaults/team` vs `/vaults/team-2` accepted; exact-duplicate reports `identical`; `RootUnexaminable` carries the cause and names no peer; `_vault_root` refuses on each of the three types and admits an absent caller; not-ready refuses in multi-user mode and is never reached for `user_id is None`; a failed re-detection retains the previous snapshot; descriptors closed on every path. **Concurrent stale-overwrite test:** two detections in flight, the older one delayed inside its root observation and completing last, MUST NOT replace the newer quarantine with its empty result — asserted both with the lock in place and, for the sequence guard, by publishing an out-of-order snapshot directly. **Deadline:** a root whose observation exceeds `VAULT_ROOT_OBSERVE_TIMEOUT_SECONDS` yields `root_unexaminable(timeout)` for that user, the detection still publishes, and every other user is observed — asserted with a fake blocking observation, not a real slow filesystem.
