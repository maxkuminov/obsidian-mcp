## 1. Foundations — schema, configuration, password policy, limiter keys, the shared lock

- [ ] 1.1 `src/models/db.py`: add `UserSession` — `id: Mapped[str] = mapped_column(String(64), primary_key=True)` (the **SHA-256 hex of** the cookie's identifier, never the identifier), `user_id` FK `users.id` `ondelete="CASCADE"`, `nullable=False`, indexed; `created_at` / `last_seen_at` / `expires_at` `DateTime(timezone=True)`, `nullable=False` (`created_at` with `server_default=func.now()`); `revoked_at` nullable; `user_agent_hash: String(64)` nullable. Index `expires_at` for the purge. Mirror 024's `MARKER` as the table comment so `alembic check` compares it.
- [ ] 1.2 `User.sessions = relationship(..., cascade="all, delete", passive_deletes=True)`. **`passive_deletes` is load-bearing**: without it `session.delete(user)` makes SQLAlchemy load every child row and delete them individually (or null a NOT NULL column), so the database cascade the migration installs would never be what fires and a divergence between ORM and schema would go unnoticed.
- [ ] 1.3 `alembic/versions/024_user_sessions.py`, in the shape 016/017/022 established — a bare `create_table` is not the house shape:
  - module-level `MARKER` string, stamped as `COMMENT ON TABLE` in the same transaction as the create;
  - where the table already exists, **verify the complete shape** (every column type and nullability; the FK's delete action through `pg_constraint.confdeltype`, not by constraint name; each index through `pg_index`) and **refuse**, naming what disagreed, rather than patching a foreign or partial shape;
  - `downgrade()` drops **only if** the marker is present;
  - the reconciliation path writes and deletes nothing, so a stamp-back re-run preserves existing rows and cannot sign live sessions out;
  - **no backfill, no data write** on any path.
- [ ] 1.4 `down_revision = "023"` — the sibling `index-integrity-hardening` migration. 024 MUST NOT merge or migrate ahead of it; if 023 is abandoned, rebase onto the then-current head and update the `schema-integrity` delta, which names the ordering.
- [ ] 1.5 Confirm the model and the migration agree on every column, nullability, server default, index **name** and the table comment — `alembic check` compares index names and the comment, and does not compare server defaults at all, which is why the gate checks the catalog directly.
- [ ] 1.6 `src/config.py`: `session_touch_interval_seconds: int = Field(60, ge=1)` and `session_purge_retain_days: int = Field(7, ge=1)`. The bounds are enforced, not assumed: a zero touch interval turns a throttled hint into a write on every request, and a zero retention window deletes a revocation the moment it is made.
- [ ] 1.7 `src/config.py`: `oauth_known_redirect_hosts: Annotated[list[str], NoDecode] = ["claude.ai", "chatgpt.com"]` with a `field_validator(mode="before")` mirroring `_parse_fts_configs` — JSON list or comma-separated string, **outer whitespace stripped** per entry, lower-cased, deduped order-preservingly. **A bare `list[str]` is JSON-decoded by pydantic-settings**, which is why `NoDecode` is there. The validator **rejects** an entry containing `*`, `/`, `@` or **internal** whitespace, with a message saying patterns are not supported; an empty list is accepted and means "nothing is recognised".
- [ ] 1.8 `src/auth/passwords.py`: `MIN_PASSWORD_LENGTH = 12` and `validate_new_password(new: str, confirm: str | None = None) -> str | None` returning a user-facing message or `None` — length, confirmation match, NUL byte. The NUL check is here because `hash_password` **raises `ValueError`** on an embedded NUL, and four handlers currently pass user input straight into it. **Do not touch the 72-byte truncation or the NUL rejection themselves**: both reproduce passlib's semantics and every stored hash depends on them.
- [ ] 1.9 `src/limiter.py`: `session_user_key(request) -> str` returning the authenticated session's user (a constant when there is none), and keep `get_remote_address` for the address-keyed limit. - [ ] 1.10 `src/oauth/grants.py`: move the account-guard advisory key and add `lock_account_guard(session)`. ## 2. Session lifecycle — mint, validate, touch, revoke

- [ ] 2.1 `src/auth/session.py`: `start_session(request, session, user)` — `sid = secrets.token_urlsafe(32)`, insert keyed on `sha256(sid).hexdigest()` with `expires_at = now + settings.session_max_age` and `user_agent_hash`, **commit the row**, then write `sid` into the cookie beside the existing keys. **The mint helper commits and the revoke helpers do not; that asymmetry is the contract.** `get_session` neither commits nor rolls back, so an insert left to the caller is an insert that may never happen — and the cookie would then authenticate nothing.
- [ ] 2.2 Same module: `revoke_session(session, sid_hash)` and `revoke_user_sessions(session, user_id)` — `UPDATE … SET revoked_at = now() WHERE … AND revoked_at IS NULL` on the **caller's** session, **neither commits**. The caller commits. This is what keeps the account guard's check-then-act atomic: nothing may commit between the lock and the protected write.
- [ ] 2.3 Same module: `touch_session(request, session, row)` — **on the request's own session, never a second one.** A second `AsyncSession` holds two pool leases for the request; with `pool_size=5, max_overflow=10` that halves an already-shared pool and every other caller in the process waits `pool_timeout=30` and then 500s. Issue the `UPDATE` only when the method is `GET`/`HEAD` **and** the row is older than `settings.session_touch_interval_seconds`, then **commit it immediately inside the dependency**, before the handler runs — safe because nothing else is pending on a safe request, and it releases the row lock before any handler can request the account-guard lock (holding it across that wait is a deadlock against an administrator revoking that same user's sessions). On any other method, or any failure: roll back to a clean state, log a WARNING, continue.
- [ ] 2.4 `get_active_session_user`: require **both** `user_id` and `sid` — a cookie with no `sid` is a pre-deploy cookie and is **refused, not grandfathered**. Then, in order: resolve the row by `sha256(sid)`; refuse when absent, when `revoked_at` is set, when `expires_at <= now`, **when `row.user_id != cookie user_id`**; then the existing user-exists / `is_active` / `session_version` checks. Every refusal keeps calling `request.session.clear()`. On success, attempt the touch.
- [ ] 2.5 `src/auth/routes.py`: `login_submit` mints through `start_session` **after** its existing `last_login_at` commit. `register_submit` mints **after** the bootstrap transaction has committed — never inside it, because that transaction holds `USER_BOOTSTRAP_LOCK_KEY` and must not be lengthened.
- [ ] 2.6 `src/auth/routes.py`: `logout` gains `session: AsyncSession = Depends(get_session)`, reads the `sid` **before** clearing, revokes that one row, commits, clears, redirects. On failure: attempt a rollback **inside its own guard** (a failing rollback must not escape either), record an ERROR carrying the exception's **class name only** — never `str(exc)` or `exc_info`, because SQLAlchemy renders bound parameters into the message and one of them is the stored session hash — then **still clear the cookie and still redirect**.
- [ ] 2.7 `src/auth/routes.py`: `login_form` stops reading `request.session.get("user_id")` directly (`:150`) and resolves through `get_active_session_user`. Without this a revoked cookie bounces between the login page and `/admin/` forever.
- [ ] 2.8 Emit `panel_session_replay_refused`, `panel_sessions_revoked` and the existing `panel_logout` through `src/services/security_events.py`. Slice 7 registers the new names in `EVENT_FIELDS`; this slice only calls them. **Never** the identifier, **its stored hash**, a password or a hash — use `token_tag`.
- [ ] 2.9 `tests/test_issue_198_session_registry.py`: the regression the issue asks for — sign in, capture the cookie, log out, **replay it → 302 to login** — plus: the minted cookie authenticates the **very next** request and the row is visible from a separately opened session; a bootstrap mint commits outside the bootstrap lock's transaction; a cookie with no `sid` is refused; an expired row is refused while its signature is still valid; a revoked row is refused; a row whose `user_id` disagrees with the cookie is refused and cleared; a live row authenticates; a second session survives the first's logout; `login_form` renders the form for a revoked cookie; the touch is skipped inside the interval, skipped on `POST`, issued and committed on a stale `GET`, and takes **no second connection**; **more concurrent stale-session requests than `pool_size + max_overflow` complete without a pool timeout**; a raising touch still serves the page; a failing logout revocation *and* a failing rollback still clear and redirect; the failure record carries only a class name; no record contains the identifier, its stored hash, or any ≥12-character substring of either.

## 3. Revocation call sites, the password policy in user administration, and the purge

- [ ] 3.1 `src/control_panel/users.py` `reset_password`: after the hash write and the `session_version` bump and **before** the existing `await session.commit()`, call `revoke_user_sessions(session, target.id)`. Add no commit — the account-guard lock is held and the guard's atomicity depends on that.
- [ ] 3.2 `edit_user_submit`: when the write clears `is_active` for the target, revoke the target's sessions in the same transaction, before its commit. Only on the deactivating transition; a vault-path edit revokes nothing.
- [ ] 3.3 `delete_user`: on the soft delete, revoke before the commit. On the permanent delete add **nothing** — the database cascade removes the rows and `passive_deletes=True` is what makes it the mechanism that fires.
- [ ] 3.4 `_lock_admin_guard` delegates to `lock_account_guard` from `src/oauth/grants.py`, **same key value**, so the self-service password change serializes against these handlers. Two keys do not exclude each other.
- [ ] 3.5 `create_user` and `reset_password` route their password input through `validate_new_password` — `create_user` accepts 8 characters today and passes its input straight to `hash_password`, so a NUL in the initial-password field is an unhandled `ValueError` and a 500.
- [ ] 3.6 Verify every refusal path still writes nothing: the last-administrator guard, the self-target refusal and the `_actor_still_privileged` re-check all return before the revocation.
- [ ] 3.7 Emit `panel_sessions_revoked` with the reason (`admin_password_reset` | `user_deactivated` | `user_deleted`) and the row count, **after** the commit that makes it true.
- [ ] 3.8 `src/services/indexer.py` `cleanup_expired_tokens`: add `DELETE FROM user_sessions WHERE expires_at < cutoff AND (revoked_at IS NULL OR revoked_at < cutoff)`, `cutoff = now() - settings.session_purge_retain_days`. **The `expires_at`-only predicate is wrong here**, unlike the OAuth half: an administrative reset revokes every unrevoked row of a user *including already-expired ones*, and such a row would be purged on the next tick — deleting the record of a revocation minutes after an operator performed it. ## 4. Self-service password change

- [ ] 4.1 `src/control_panel/routes.py`: `GET /admin/account` rendering `account.html` through `_panel_context(request, user, {"active": "account", ...})` — gated by the router-wide `require_user_panel`, **not** `require_admin_panel`. In single-user mode render without the password card.
- [ ] 4.2 `POST /admin/account/password` taking `current_password`, `new_password`, `new_password_confirm`; CSRF from the router-wide `verify_csrf`. **Two stacked limits**, both at `5/minute`: one `key_func=session_user_key`, one `key_func=get_remote_address`. Neither subsumes the other — an account-only key lets one address walk many accounts, and any key containing the address hands an attacker a fresh allowance per address, which is why the single composite key of the first draft did not bound guessing against one account. 404 when `settings.multi_user_mode` is false.
- [ ] 4.3 **The critical section, in one transaction:** `lock_account_guard(session)`; re-read the acting user `SELECT … FOR UPDATE` with **`execution_options(populate_existing=True)`** — without it SQLAlchemy hands back the dependency-loaded object's **pre-lock** attribute values and the re-read proves nothing; refuse if the row is gone or `is_active` is not exactly true (the actor may have been deactivated while this request queued); verify `current_password` against the **freshly read** hash. Verifying against the dependency-loaded hash is how a concurrent admin reset gets silently overwritten and access the administrator just removed comes back.
- [ ] 4.4 Refusals, each `flash(...)` + `303` back to `/admin/account`, never a query parameter (#138): `validate_new_password` message; current password does not verify; the new password verifies against the stored hash (reuse); row gone or inactive. One constant message for the credential failure. Nothing commits between the lock and the write.
- [ ] 4.5 Success, still in that transaction: `password_hash = hash_password(new)`, `session_version += 1`, `revoke_user_sessions(session, user.id)` — **all** rows, this session's included — then commit, which releases the lock. **After** the commit, `start_session(...)` in a second transaction mints a fresh identifier and row. If the mint raises, the user is signed out; do **not** roll the password change back.

## 5. Consent identity, registration hardening, allow-list, badge and warning

- [ ] 5.1 `src/oauth/trust.py` (new): `known_redirect_host(redirect_uri)` and `redirect_display_host(redirect_uri)`. The display host is `urlparse(uri).hostname`, lower-cased — **`hostname`, never `netloc`**, so `https://claude.ai@evil.example/cb` reads `evil.example`. A non-ASCII host is returned in its punycode (`xn--`) form and is **never** decoded. An empty or unresolvable host returns a sentinel that the template renders as "could not be determined" and that `known_redirect_host` always answers false for. Matching is case-insensitive **equality** against `settings.oauth_known_redirect_hosts` — no suffix, prefix, substring or wildcard.
- [ ] 5.2 `src/oauth/routes.py` `_valid_redirect_uri`: additionally require a **non-empty `hostname`** and a **successful IDNA-to-ASCII conversion**, storing the converted form. `https://@/cb` registers today — its `netloc` is `"@"` and truthy while its `hostname` is empty — and would render a consent card with no destination at all. Normalising at registration also stops a host being stored in two forms that render alike and compare differently.
- [ ] 5.3 `src/oauth/routes.py` `authorize_get`: pass `redirect_host`, `client_registered_at` (`client.created_at`, date only) and `client_trust` (`"known"` / `"unverified"`) alongside the `client_id` it already passes. - [ ] 5.4 `src/control_panel/templates/authorize.html`: an identity block above the request box — application name (as today), the **destination host** in its own labelled element, the client identifier, the registration date; the **unconditional** self-registration notice; then either the known-client badge or the warning naming the host and stating the code will be delivered there.
