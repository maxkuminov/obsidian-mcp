## 1. Reuse detection in the token endpoint

- [x] 1.1 `src/oauth/routes.py` `_handle_refresh`: resolve the refresh row by token hash + token type **alone** (no `revoked` predicate, no caller-supplied `client_id`), take the family lock, re-read the row under it, and branch on `old_token.revoked` — call `revoke_grant_family(session, grant_id)` and commit before returning `invalid_grant`. A row that vanished under the lock is a not-found refusal, not reuse.
- [x] 1.2 Move the caller-supplied `client_id` check to an explicit comparison against the live row, after the reuse branch: a mismatch on a live token stays `invalid_grant` and revokes nothing.
- [x] 1.3 Keep the response identical in status, headers and body to the not-found refusal, and guard **every** database call on the detection path — the revocation, the commit, and both rollbacks — so no failure after detection can escape to the outer handler and answer 500 on this path only.
- [x] 1.4 Commit only when live tokens were actually revoked; an already-fully-revoked family rolls back a no-op. Confirm no new lock is taken: the grant lock is held from before the authoritative re-read, and `revoke_grant_family`'s `lock_grant` is the same re-entrant transaction-scoped key.
- [x] 1.5 Add a module logger and emit one WARNING `oauth.refresh_reuse_detected` on that path only, with `client_id`, `grant_id`, `user_id` and `revoked_tokens` **in the message text** (the deployed formatter is `%(message)s`) as well as in `extra` — never a token value or hash. A revocation that raises logs `oauth.refresh_reuse_revocation_failed` with the exception's **class name only**: no `exc_info`, no `str(exc)`, since SQLAlchemy renders bound parameters (including the token hash) into it.
