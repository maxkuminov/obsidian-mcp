## Why

The 2026-09-04 OWASP ASVS 5.0 assessment left four medium-severity findings open, and they are one story told four times: **the embed pass reports success it did not achieve, and every consumer downstream of it believes the report.** Production is multi-user and the consumer is an agent, so each one lands on the failure this project ranks second — *silently wrong search results an agent acts on without a human ever seeing the query* (`CLAUDE.md`).

- **#201** — `embed_note` catches the provider exception itself and returns zero chunks, so `embed_vault` never reaches its `record_failure` branch and `outcome.embedded += 1` runs anyway. A total Ollama/OpenAI outage writes `indexer_runs` rows reading `notes_embedded = N, error = NULL`: byte for byte a healthy pass, with a *positive* count, which is more misleading than the zero #160 was designed against. The pass record built to end "a wall of healthy passes" reports a wall of healthy passes.
- **#200** — both vector paths return stored `chunk_text[:500]` with no `embedded_content_hash` predicate. During the window #201 hides, an agent is handed superseded note text as a current result with nothing marking it. Every other field on that row — path, title, tags, frontmatter — was refreshed by the scan; only the chunk text is stale, and only the chunk text is quotable as the note's content.
- **#202** — `chunk_text` has no cap, `MAX_NOTE_BYTES` is 10 MiB (~5,120 chunks at 512 tokens), Ollama embeds them one sequential 30 s-bounded call at a time, the backlog SELECT has no `LIMIT`, and `_active_user_ids()` has no `ORDER BY` and no rotation cursor. Re-editing one huge note keeps every later tenant's new and edited notes out of `notes_metadata`, tsvector and embeddings indefinitely, under the global `index_pass_lock`, visible only as missing `indexer_runs` rows.
- **#206** — `note_embeddings` records nothing about the provider, model, chunk size or overlap that produced it, and `content_tsvector` records nothing about `FTS_CONFIGS`. Startup catches a **dimension** change and validates FTS config *names*; a same-dimension model swap (bge-m3 → another 1024-dim model) is caught by nothing, mixes two vector spaces in one column permanently, and makes cosine distance meaningless. The `.env.example` reset warning sits beside `CHUNK_SIZE` and `EMBEDDING_PROVIDER` and **not** beside `EMBEDDING_MODEL`, which is the unguarded knob.

The project already adopted "derived rows are fingerprinted to their generating config" for the fence cleaner (#150, `extraction_version`) and "a bound is a *declared* degradation with a durable marker" for link extraction (#203, `links_truncated`). This change applies both principles to the embedding path and makes the pass record tell the truth.

## What Changes

- **Provider failure is a typed outcome carrying its own error detail, not a count.** `embed_note` returns an `EmbedNoteResult` naming what happened — embedded, certified-with-zero-chunks, **provider-failed**, or **provider-cardinality-mismatch** — with a bounded failure record (exception class, truncated message, requested/received chunk counts) attached to the two failing outcomes, instead of an int that conflates the first of those with the third. `embed_vault` counts only the certifying outcomes into `notes_embedded` and feeds the failures into the pass's accumulator, so the run row carries a `error` that names something. **The reconciliation sweep feeds the same accumulator**, since on a fully-indexed vault it is the only thing making provider calls and an outage there produced a clean run row too. The `_record_index_run` heartbeat stays green through an outage, as #160 deliberately decided; the run row is what turns red.
- **Stale chunks are annotated, never filtered.** `semantic_search` and `find_related` load `embedded_content_hash` alongside `content_hash` and mark any row where they are distinct; `find_related` also states, **on every return path including the empty one**, when the *source* note's own vectors predate its current bytes. **The chunk preview is withheld on a stale row** and replaced by an explicit notice naming `read_note`; path, title, similarity and tags are kept, because the scan already refreshed them and they are true of the note as it stands. Filtering was rejected: on hash equality it would hide every note edited in the last five minutes, the whole vault during an outage, and would trip the O(n) exact fallback on every query. The guarantee is scoped to what the scan has committed — an edit the scan has not yet seen is a declared, documented and tested residual, not a silent one.
- **A per-note chunk cap, a persisted rotation cursor, and a note-boundary budget.** `MAX_CHUNKS_PER_NOTE` bounds `chunk_text` in document order; an over-cap note is a **declared, durable degradation** exactly like the link cap — first N chunks embedded, the note **certified** (never held uncertified, which is #127's permanent burn), `notes_metadata.chunks_truncated` set, one ERROR line after the certifying commit, and `embedding_truncated: true` on every vector-search row for that note. `CHUNK_OVERLAP` is constrained below `CHUNK_SIZE`, because the equal case collapses the chunker's step to one character and makes 3 KB of prose hit the cap. `_active_user_ids()` orders deterministically and starts after the user id recorded in a persisted cursor, so the rotation survives a restart. A per-user chunk and wall-clock budget is checked **only at the note boundary where `_is_paused()` already sits**, after at least one note, so no note is ever preempted mid-chunks and no tenant is livelocked to zero progress. The fairness claim is scoped to the embed stage; the scan and the link backfill stay unbudgeted and that is recorded rather than implied.
- **One settings fingerprint per derived kind, compared at startup, both failing closed.** A new `indexer_state` key/value table (migration 023) holds `embedding_fingerprint` (provider, model, dimensions, chunk size, chunk overlap, chunk cap), `fts_fingerprint` (the sorted `FTS_CONFIGS` list) and `embed_rotation_cursor`. Startup compares both in the same shape as `_check_embedding_dim` and **exits non-zero** on either mismatch, naming both sides, the differing fields, and `make reset-embeddings` or `make rebuild-tsvectors`. A stale stemmer is not merely incomplete: `running` stored as `run` makes a `simple` query for `run` match a note that does not contain the word, which is a false positive an agent acts on. Absence is adopted, not refused; an unparseable or unknown-version value is refused and never overwritten. The repair workflows are the only writers, so a refusal cannot clear itself — and the keyword fingerprint is written only by an operation that rebuilt **every scope holding rows**, in one transaction, with each scope reporting a typed completed-or-skipped outcome, because a per-owner rebuild cannot claim anything about the table and its "skipped, provenance unsettled" already looks like `0 rows`. A startup check alone is not enough, so a **single transaction-scoped advisory lock** — taken by every reset and rebuild before it mutates, and by every certifying or keyword-vector-writing transaction after its provider call and before its write, with the fingerprint re-read under it — closes the window between a check and the act it authorises. Per-row fingerprints are rejected as over-engineering for a global setting. `.env.example` and `README.md` gain the reset warning at `EMBEDDING_MODEL` and `OPENAI_EMBEDDING_MODEL`, plus the operator rule for the one case no check can see: a model artifact replaced behind an unchanged name.
- **The dashboard reports currency, not just presence.** The coverage bar measures rows that *have* vectors; the pending (stale) count — the same query the reset-progress poller already serves — is shown beside it, so an outage that #201 now records in `indexer_runs` is also visible on the page an operator opens first.

One additive migration (023, `indexer_state`). No new dependencies.

### Modified Capabilities

- `index-integrity`: full chunk coverage is redefined over the bounded requested set; provider failure is a distinct per-note outcome carrying bounded error detail, excluded from the pass's embedded count and counted by the sweep as well as the backlog; chunking is capped per note as a declared degradation that still certifies; the embed pass rotates tenants from a persisted cursor and honours a per-tenant embed-stage budget checked only at the note boundary.
- `search-quality`: both vector paths annotate a stale row and withhold its chunk preview rather than filtering it out; `find_related` states a stale source on every return path; a capped note's rows are marked; the guarantee's scope is stated.
- `embedding-providers`: a stored settings fingerprint gates startup for embeddings and for keyword vectors, both failing closed; a single database-level generation lock makes the fingerprint an interlock rather than a startup check, held by every reset, every rebuild and every derived-row write; the reset and rebuild workflows own their fingerprint, the rebuild only after every retained scope reported a completed rebuild; the CLI reset matches the panel's conditional index creation; the model knobs carry the reset warning and the artifact rule.
- `schema-integrity`: migration 023 owns the `indexer_state` table and the `chunks_truncated` column as marked units and backfills nothing; the schema gate's asserted head moves to 023.
- `panel-ops-health`: the dashboard shows the pending (stale) embedding count beside the coverage bar and the count of notes whose embeddings are truncated.
