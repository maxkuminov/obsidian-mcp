## 5. Integration test (opt-in, reuses the pgvector harness from `dependency-refresh-2026-08`; add it identically here if that change has not merged)

- [x] 5.1 `tests/integration/test_search_recall.py` (vector benchmark): a fixed, seeded corpus (`random.Random(1234)`), ≥ 400 `A/` chunks and ~30 `B/` chunks plus tag/frontmatter/user variants, deterministic insertion order, index built with fixed `m`/`ef_construction`; a fixed list of ≥ 5 query vectors chosen so `A/` dominates their nearest neighbours; `ANALYZE`; assert `EXPLAIN` uses the HNSW index for the filtered query; assert with `hnsw.iterative_scan = off` at least one query returns empty/short vs the baseline (fixture reproduces the bug); compute the exact baseline as a sequential scan (`enable_indexscan=off`) taking the same overfetch of nearest chunks + same dedupe/truncation; assert set-recall ≥ 0.9 per query with cutoff ties counted equivalent; assert the baseline `EXPLAIN` excludes the HNSW index; assert the zero-row exact fallback triggers (construct a filter matching one note far from the query; force `hnsw.max_scan_tuples` low; assert the note is still returned and `exact_fallback` recorded); repeat across three index rebuilds (drop/recreate the index); repeat for tags, frontmatter, user scope; assert monotone distances. The `EXPLAIN`-uses-HNSW assertion covers **every** filter shape, not one: the shapes do not share a plan, and the user scope was landing on seq scan + sort (an exact plan, recall 1.0 for free) until `alice` was given the `A/` crowd and `bob` all of `B/` — the planner's estimate of what the scope selects is what chooses the plan. `find_related` gets the same treatment through its **production** entry point: `current_user_id` set to a corpus user, `tools.find_related_impl` called for a fixed set of that user's source notes on each of the three rebuilds, scored against an exact baseline that re-runs `tools.find_related_stmt` (the statement the tool itself issues, factored out for this) with `enable_indexscan = off` in its own transaction at the same overfetch with the same per-note dedupe — asserting set-recall ≥ 0.9 with cutoff ties equivalent, non-empty, monotone, every result inside the user scope, and `EXPLAIN` of that statement naming the HNSW index. Its sources are `B/hub-*` notes, each with a ladder of satellites at separated cosines, because `find_related` supplies its own query vector (the mean of the source's chunks) and a corpus of uniform-random 1,024-dim vectors puts the ten nearest notes inside a 0.006-wide band — which ten an approximate scan returns is then noise, measured at 0.8–1.0 across rebuilds of the same corpus. The ladder makes "the ten nearest" a fact about the corpus; a fixture-integrity assertion fails if the surrounding notes ever crowd into it.
