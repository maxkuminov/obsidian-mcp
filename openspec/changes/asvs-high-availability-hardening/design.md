## Context

Single uvicorn worker, one asyncio loop shared by every tenant's MCP tool calls, OAuth, the panel, and the indexer task (`src/main.py`). A CPU-bound or pool-holding operation triggered by one tenant is therefore felt by all. The four findings are the four ways a tenant can do that today with legal input; each was measured on the production host (see the assessment report in the vault and issues #180, #203, #204, #208). Constraints that shape the fix:

- The frozen v0 cleaner (`_v0_clean`) must produce **byte-identical** output forever — `extraction_version` comparisons and the documented rollback recipe depend on it (`index-integrity`, "A masker grammar change forces re-derivation…").
- The link rebuild certifies "every link row was written by this pass" and any *skip* withholds a re-derive's certification (`index-integrity`, A.7a). A cap must not become a permanent self-inflicted uncertified state for a tenant with one large MOC note.
- A link-grammar change has the same staleness mechanics as a fence-grammar change: `content_hash` does not see it, so stale `note_links` rows would persist until each note is edited.
- `_vault_root` and the `_tracked` admission gate must stay cheap; nothing here may add a DB query to them.
- The upload route's claim/validate/publish sequence is a linearizability argument (`file-transfer`); reordering must keep "claim first, before any body byte", the locked publish gate, the uniform-404 rule for non-usable tokens, and the single-clock-domain deadline rule intact.

A pre-code audit of the first draft of this design found that it left four quadratic character classes untouched, proposed an idle-transaction timeout that would have killed the indexer's steady-state pass, and mis-stated the memory bound; this revision incorporates every finding.

## Goals / Non-Goals

**Goals:**
- No input under the documented caps can hold the event loop for more than a small constant per note, or hold a pool connection while waiting on I/O it does not need.
- Every bound is a *declared* one: refused with a message naming the limit, or degraded with a durable, agent-visible marker plus an ERROR log line — never silent.
- Byte-identical v0 cleaner output, proven by a differential test, not by inspection.
- Existing `note_links` rows are re-derived under the new grammar by the versioned mechanism the index already has.

**Non-Goals:**
- Per-tenant fairness or round-robin in the indexer (#202) and a general `/mcp` rate limiter (#188/#194) — separate changes.
- Bounding `path_to_content` — the indexer buffers every changed note's parsed body for the pass (`indexer.py:1537`, released at `:1833`), and a re-derive holds the whole vault's bodies. That buffer is bounded by the write-side caps × changed notes and is unchanged here; this change bounds **link-row** memory only. Recorded as an accepted residual on #203.
- An `idle_in_transaction_session_timeout`. Dropped: the steady-state index pass holds one transaction from its first select to its commit across the whole synchronous walk (`indexer.py:1448` → `:1926`, minutes on a large vault), the embed pass calls the provider before its first statement, and the backfill scans the vault before its first insert. A timeout would kill all three on the COMMIT and reproduce every tick.
- Bringing `_MDLINK_REWRITE_RE` to full parity with `_MDLINK_RE` (the rewrite path does not rewrite the CommonMark `<...>` href form, and its anchor class crosses newlines where extraction's does not). Both are pre-existing gaps recorded in a test as known divergences; fixing them changes `move_note` behaviour and needs its own change.
- Indexer-side handling of `.md` files over `MAX_NOTE_BYTES` placed by Obsidian or sync. Every *tool* ingress is capped by this change (D5); memory is bounded by the link cap regardless of note size.

## Decisions

**D1 — Every unbounded character class in the four link regexes becomes bracket-free or length-bounded, with possessive quantifiers.**
The quadratic case is any run where a class consumes the rest of the line and then the tail fails: `[[` (target), `[[a#` (anchor), `[[a|` (alias), `[a](` and `[a](x` (href). Measured at 40 KB: 18 s, 11.8 s, 4.9 s, 3.6 s, 2.4 s; with every class closed, ≤ 3 ms. Rules, applied identically to `_WIKILINK_RE`/`_MDLINK_RE` in `links.py` and `_WIKILINK_REWRITE_RE`/`_MDLINK_REWRITE_RE` in `tools.py`:
- Wikilink **target, anchor and alias** classes exclude `[` and `]` (`[^\[\]\|#\n]++`, `[^\[\]\|\n]*+`, `[^\[\]\n]*+`). Obsidian's *link syntax* forbids `[`/`]` inside `[[...]]`, so no well-formed wikilink changes. Accepted differences, each pinned in a test: `[[Note|see [1]]]` and `[[Note#Sec [x]]]` (a bracket inside an alias or anchor) are no longer extracted — today they yield a row with a mangled alias/anchor.
- Markdown **link text** excludes `[`: `[a[b](x.md)` still yields a link to `x.md`, but its stored `link_text` becomes `[b](x.md)` instead of `[a[b](x.md)`. That is the field `get_links`/`get_backlinks` return and `move_note` splices on; pinned in a test.
- Markdown **href** cannot exclude brackets — `[t](Foo [draft].md)` is a legal link to a legal filename (Obsidian forbids brackets in wikilink syntax, not in filenames). The href classes are instead **length-bounded**: `[^)\n]{1,2048}?\.md` and `[^>\n]{1,2048}?\.md`. A bounded lazy scan is O(n × 2048) worst case (≈ tens of ms at 40 KB) and identical for every href up to 2,048 chars, which exceeds `MAX_PATH_CHARS` (1,024) plus any anchor. Accepted difference: an href over 2,048 chars is not extracted (it cannot name a note).
**Residual found at implementation, and D1b that closes it:** the bounded lazy href scan is linear but with a large constant — measured 4.7 s per 512 KiB of `[a](`, ≈ 90 s for a 10 MiB note — and `asyncio.to_thread` does not help because CPython's `re` holds the GIL for the whole of a single `finditer` step (a zero-match scan is one step). A 90 s cross-tenant stall per edit of one note is not an acceptable bound. **D1b:** the markdown-link grammar is implemented as a hand-written linear scanner shared by extraction and rewrite, with the retired regexes kept as test oracles and a differential property test; its absolute ceiling (1 MiB of `[a](` under 200 ms) is a DoS bound, not a regression backstop. The wikilink regexes need no scanner: with every class closed they measure ≈ 130 ms per MiB.
A fourth accepted difference surfaced in implementation and is pinned: `[[[Foo]]` now yields target `Foo` (the match starts one `[` later); previously `[Foo`, which could never name a note.
*Alternatives considered:* a per-line length guard (#180's suggestion) — rejected as the primary fix because it changes which valid long lines are parsed at all; the class-level fix removes the superlinear step everywhere. `asyncio.to_thread` alone — moves the burn off the loop but one tenant still consumes the worker's CPU for minutes (Codex challenge on #180); kept as D3 for the residual linear cost.

**D2 — Reimplement `_v0_clean` as a line scanner over `\n` only, and prove equivalence differentially.**
The regex pair `^```[^\n]*\n.*?\n```\s*$` / same with `~~~` (MULTILINE|DOTALL, applied sequentially with `re.sub`) is quadratic in the number of unclosed openers because each `.*?` walks to end-of-input. The scanner must reproduce the regex's exact semantics, which an empirical characterisation established: split on `\n` **only** (never `str.splitlines()`, never `_LINE_BREAK_RE` — a lone `\r`, `\v`, `\f`, ` ` is *not* a line break to the regex); leftmost opener, nearest closer line that is exactly the fence run followed by `\s*` to a line end where `\s` is Unicode-aware (so `` ```\xa0 ``, `` ```\x0b `` *do* close — the opposite of the v1 grammar), with `\s*$` allowed to swallow following blank lines; an empty block (opener immediately followed by closer) is *not* removed; a closer run longer than the opener does not close; backtick pass then tilde pass. The differential test keeps the two regexes as the oracle (in the test module only) and generates inputs from these classes: unclosed openers, orphan closers, nested and adjacent mixed backtick/tilde fences, trailing whitespace and NBSP/`\x0b`/` ` on closer lines, blank-line runs after closers, CRLF and lone `\r`, indented fences, empty blocks, over-long closer runs — plus every existing v0/v1 fixture. The v0 cleaner is reachable today through `clean_at_version` whenever a row's stamped version is 0 or the rollback recipe is exercised.

**D3 — Run extraction and rewrite computation via `asyncio.to_thread`.**
`extract_links`, `extract_tags` and the rewrite computation are pure functions of a string. Caveat recorded at implementation: a thread only yields between `re` calls (each `finditer` match), never inside one, so `to_thread` bounds the stall to the longest single scan step, not to zero; D1/D1b make that step short.  The indexer's changed-path loop and backfill, and `move_note`'s rewrite planning, dispatch them through `to_thread`. The spec's observable is the dispatch itself (a test asserts the call goes through `to_thread`), not a race against a concurrent request, because a timing assertion is unreliable on CI.

**D4 — `MAX_LINKS_PER_NOTE = 10_000` in document order; per-note flush; over-cap is a declared, durable degradation.**
`extract_links` returns wikilinks and markdown links from two sequential loops, so "first N" must be defined: the bounded extraction **merges by `position` and keeps the first N in document order**, so a note with 20,000 wikilinks does not lose every markdown link. The indexer inserts each note's rows immediately (≤ 1000-row batches) inside the loop, so peak **link-row** memory is one note's worth. An over-cap note: the first N rows are persisted, `notes_metadata.links_truncated` (new boolean column, migration 022) is set, one ERROR line names the path and the cap (not the true total, which would need the unbounded extraction the cap prevents), and `get_links` for that note returns `truncated: true`. The note is **not** a skip. *Why not a skip:* A.7a's skip withholds re-derive certification, which for a tenant with one generated MOC would leave provenance unrepaired indefinitely — a self-DoS on the index-integrity machinery. The truncation is deterministic and the rows written are exactly the rows derived, so the pass's structural claim still holds; A.7a is amended to say so. *Why a column and not only a log:* the ERROR ring buffer is 100 entries and process-lifetime; the graph tools would otherwise report a truncated set as complete, which is the silently-wrong-result failure ranked highest in `CLAUDE.md`. ERROR rather than WARNING so it also reaches the ops-health buffer.

**D5 — The `.md` note cap binds every tool ingress, as `min(MAX_NOTE_BYTES, MAX_FILE_WRITE_BYTES)`.**
`vault-write` states every note-writing path has a tool-level cap; `write_file`, the transfer upload, and `import_from_url` were the exceptions because they are byte transport with no extension allowlist. The indexer treats any `.md` as a note, so the cap follows the extension (case-insensitive), not the tool. The bound is the smaller of the two so an operator who lowers `MAX_FILE_WRITE_BYTES` below 10 MiB is not surprised by a *more* permissive `.md` limit. For the transfer path the cap is applied where the stream cap is applied (`max_bytes` at the route and in `import_from_url`), so a `.md` upload aborts with 413 at cap+1 exactly as an oversized file does.

**D6 — `MAX_LIST_PATTERN_CHARS = 1024`, enforced in `list_dir` as a `ValueError`, before path validation.**
`fnmatch.translate` + `re.compile` is linear at ≈10 µs/char (Python 3.12 emits atomic groups, so there is no backtracking to cap); 1,024 chars compiles in ~5 ms. `list_dir` raises `ValueError` — the exception `list_files_impl` already maps to an in-band refusal — and does so before `validate_visible_path`/`is_dir`, so an over-long pattern is refused by its own cause regardless of the folder. A wildcard-count cap is redundant; `to_thread` for the walk is defense-in-depth only and not part of this change.

**D7 — Upload: session per phase; bounded, deadline-aware slot wait inside `stream_to_vault`; precedence rule for 408 vs 503.**
Phase 1 (claim, `resolve_identity_ok`, `resolve_root_ok`, `_path_ok`, and `check_publication_support`) commits and exits the session before any wait or body byte. The claimed `TransferToken` is used detached: it has no relationships and no deferred columns, `claim_upload`'s own commit already leaves it readable under `expire_on_commit=False`, and `close()` expunges without expiring; only plain columns are read afterwards. The stream runs with no session. `release_claim`/`consume` and the publish gate each open their own short session (the gate already does; the handlers keep taking the row and only read its id). The semaphore acquire **stays where it is** (`transfer.py:1246`, inside `stream_to_vault`, so `import_from_url` and the ~40 direct test call sites keep their bound); it gains a `slot_timeout` and acquires in ≤ 1 s slices, recomputing `_deadline_remaining` (wall clock) on each slice so the single-clock-domain rule is not re-broken by a monotonic `wait_for`. Precedence on a wait that ends without a slot: re-check the deadline first — overrun → the existing 408/`consumed` path; only a wait cut short by the 30 s cap raises `QueueTimeout`, which the route maps to 503 with `Retry-After: 5` and **releases the claim to `pending`** because the capability's window is still open and nothing was staged. The 503 is only ever produced after the claim and re-validation succeeded, so the uniform-404 rule for non-usable tokens is unaffected. The "deadline already overrun before the wait" case cannot occur in production (`claim_upload` guarantees a positive remainder the instant phase 1 ends) and is produced in tests by patching `transfer.now_utc`, the endorsed hook.

**D8 — Engine: `pool_timeout=30` made explicit as documentation.** It is already SQLAlchemy's default; writing it down is the whole change. No idle-transaction timeout (see Non-Goals).

**D9 — Bump `CURRENT_EXTRACTION_VERSION` to 2 with a v2 cleaner identical to v1.**
The link grammar changed, so every note's `note_links` must be re-derived once; the versioned marker is the mechanism the index already has for exactly this. The v2 cleaning function is the v1 function under a new key, so the cleaned-output comparison finds no difference and **no note is re-embedded**; the pass re-extracts links and tags for every note once and stamps the marker. `move_note(rewrite_links=True)` refuses during that window per the existing requirement, which is the correct disposition for a grammar change.

## Risks / Trade-offs

- [D1 alters a link somebody relied on] → the differences are enumerated and tested: bracketed alias/anchor (row disappears), `[a[b](x.md)` (`link_text` shortens), href > 2,048 chars (not extracted). All are malformed or impossible as note names; the full existing link and rewrite suites run unchanged.
- [D2 scanner differs from the regex on an untested input] → generator classes above include every class the empirical characterisation found surprising; the oracle regexes stay in the test so any future drift fails loudly.
- [D4 truncation makes `get_backlinks` incomplete for a giant MOC] → durable `links_truncated` flag surfaced by `get_links`, ERROR line, docs; 10,000 outgoing links per note is far beyond any real note in either production vault.
- [D4 migration 022 on a deploy] → additive nullable-with-default column; `make test-schema` gates it; `alembic check` must be clean after deploy.
- [D5 refuses an upload a client started] → 413 at cap+1, same as an oversized file today; the limit is named in `request_upload`'s response.
- [D7 detached row] → covered above; a test uploads with the session closed and asserts every column the route reads is present.
- [D7 503 releases a claim a concurrent `check_upload` sees as `pending` again] → documented retryable state; nothing was streamed.
- [D9 one full re-extraction pass] → links and tags only, no embedding calls; `move_note(rewrite_links=True)` is refused until it completes, as the existing requirement mandates.
- [M6-style flake: linearity benchmarks on a shared CI runner] → each benchmark asserts a *ratio* (time at 2n ÷ time at n < 4) with a generous absolute ceiling as backstop, not a single wall-clock point.

## Migration Plan

Migration 022 adds `notes_metadata.links_truncated BOOLEAN NOT NULL DEFAULT FALSE`. Run `make test-schema` before deploy; `make deploy` backs up, migrates, recreates; `make db-check` must be clean after. The first pass after deploy re-derives links and tags for every note (D9) — expect one long pass and `move_note(rewrite_links=True)` refusals until it completes. Rollback: revert the code; the column is harmless; `CURRENT_EXTRACTION_VERSION` back to 1 with the frozen cleaners in place is the documented rollback recipe.
