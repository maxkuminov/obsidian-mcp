# Implementation contract

Authlib 1.9.2 async OAuth2 client handles authorization URL/PKCE and token exchange; joserfc 1.7.7 handles signature verification, followed by Authlib CodeIDToken validation (issuer/audience/exp/iat/nonce/azp/at_hash). HTTPX2 2.16.0 is the maintained transport selected by current Authlib. Existing HTTPX callers stay unchanged. Sources: https://docs.authlib.org/en/stable/oauth2/client/http/index.html and https://jose.authlib.org/en/guide/jwt/ .

Configuration names: OIDC_ENABLED=false, OIDC_ISSUER, OIDC_CLIENT_ID, OIDC_CLIENT_SECRET (redacted repr), OIDC_REQUIRED_GROUP, OIDC_SUBJECT_USER_IDS (JSON object), LOCAL_LOGIN_ENABLED=true. Activation requires MULTI_USER_MODE=true and MCP_SANDBOX_MODE=false; BASE_URL must be an HTTPS origin with no userinfo/query/fragment/path. Issuer is an exact HTTPS URL with no userinfo/query/fragment; trailing slash is preserved for issuer equality. All discovered endpoints remain on its origin and have no userinfo/fragment. PKCE is S256, client authentication client_secret_basic, scopes openid profile, group claim named groups and array of strings in ID token, signature RS256 only.

Routes GET /admin/auth/oidc/start?next=… and GET /admin/auth/oidc/callback. Login page links to the start route (not a form submission, preserving form-action self). State is consumed without await under the single-worker contract before network I/O. Cross-browser mismatches are denied without authorizing or minting. Whole network phase deadline 20 seconds; HTTP per-operation timeout 5 seconds. Bound provider JSON response sizes and token lengths. Transactions capped at 1024; at capacity refuse new login instead of evicting live ones. Endpoints have per-address limiter. All failures use generic UI and bounded security event reason, no raw upstream exception strings.

Browser transactions only establish local app sessions; OIDC tokens discarded. Logout stays local and may immediately SSO again while provider session exists. Account/group removal at issuer does not terminate local credentials. Operator offboarding must deactivate/revoke locally. No schema changes. The account's existing admin flag and vault ownership are never copied from claims.
